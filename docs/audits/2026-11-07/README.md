# 実際にアプリを作って確かめたチェック(2026-11-07・v0.61.0 時点)

1.0.0 の前に、ライブラリを実際に使って 8 本のアプリを作り、利用者の目で不具合・ドキュメントの食い違い・使いにくさを探した記録。前回の最終チェック(`docs/audits/2026-11-05/`)はコードの見直しとハーネスと乱択の操作で、実際に使って作ることはしていなかった(ユーザーの問いかけで分かった)。所見は 83 件(高 0 / 中 29 / 低 54。不具合 DF-01〜25・ドキュメント DD-01〜26・使いにくさ DU-01〜32)。ユーザーへの報告は Claude Docs の「アプリを作って確かめたチェック」で、表の「対応」の列で選んでもらった(§3)。

## 1. 進め方と前提

- 対象: npm の公開版 0.61.0(main の 4762d73)。
- 8 本のアプリを、リポジトリのソースを見ない担当(サブエージェント。4 本ずつ 2 回)が、npm の公開版とドキュメント(README / API_REFERENCE.md / 同梱の Skill / ドキュメントサイトの内容)だけで作った。Mantine の在庫表(5,000 行・全エディタ・検査)/ SSRM の受注一覧(20 万行の擬似サーバー・書き戻し)/ 顧客の Master/Detail(展開行の中にグリッド・行ドラッグ)/ グループ集計のレポート / `/lite` の最小構成 / `/ai` の絞り込み / Next.js 16(App Router・SSR・テーマ)/ React 18.3。
- どのアプリも tsc(strict・`skipLibCheck: false`)と本番ビルドを通し、実際の Chromium(Playwright)で操作して、スクリーンショットと console のエラー / 警告も見た。
- 担当の報告は 99 件で、重複をまとめて 83 件。裏付けは私がコードかドキュメントを読んで確かめた(表の「裏付け」の列。「担当の再現」はタイミングに依るものなどで、担当の Playwright の再現に拠ったもの)。
