# 1.0.0 前の最終不具合チェック(2026-11-05・v0.60.0 時点)

1.0.0 に上げる前に、公開している機能を一通り見直した記録。所見は FC-01〜FC-35(高 2 / 中 14 / 低 19)。どれも 0.60.0 での回帰ではなく、前回の全体監査(`docs/audits/2026-10-04/`)より前からあるか、その後に入った機能の端のケース。ユーザーへの報告は Claude Docs の「1.0.0 前の最終不具合チェック」で、表の「対応」の列で選んでもらった(§4)。

## 1. 進め方と前提

- 対象: main の 65ae7f5(v0.60.0 + ドキュメントの変更のみ)。下の表の行番号はこの版のもの。
- 別視点のコードレビューを 5 系統(編集・入力・クリップボード / SSRM / ドラッグ・モーション / フィルター・状態・グルーピング / 表示・集計・フィル・エクスポート)に分けて行い、所見ごとに vitest(jsdom)の再現テストを書いて確かめた。
- 高の 2 件と FC-03 は実際の Chromium(監査ハーネスと同じ dev サーバー)で再現した。FC-16 は Node で再現した。FC-13 は Safari の実機では確かめていない(WebKitGTK の WebDriver は IME の変換を送れない)。
- 乱択の操作: 400 手 × 20 回(編集・貼り付け・クリア・フィル・ソート・undo / redo・検索・スクロール。通常 / グルーピング / ラベル行 / 展開行 / auto-height / 行ドラッグ / SSRM)。最後にすべて取り消して最初のデータに戻るか、すべてやり直して取り消す前に戻るかも見た。スクリプトはリポジトリに入れていない。
- 公開する tarball(0.60.0 を pack)を、TypeScript 5.0 / 5.4 / 5.8 / 6.0 × moduleResolution bundler / node16 / nodenext × `exactOptionalPropertyTypes` × `@types/react` 18 / 19 × `skipLibCheck: false`、Node の ESM / CJS、SSR(React 19.2 / 18.3)で確かめた。
