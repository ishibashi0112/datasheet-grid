## 1. 作ったもの

- **構成**: Vite 7.3.7、React 19.3.1(StrictMode)、TypeScript 5.9(`strict`、`skipLibCheck: false` で tsc は通った)、npm。UI ライブラリは使っていない。`@ishibashi0112/spreadsheet-grid@1.0.0` の全部入り(`.`)と `style.css`。日本語(既定)。
- **データ**: ログ 1,000,000 行(時刻 / レベル / サービス / メッセージ / traceId)。決まった乱数で作り、7 日分で、時刻は `'YYYY-MM-DD HH:mm:ss.SSS'` の文字列にした。メッセージは長文で、英語と日本語、改行入りのスタックを含む。
- **使った機能**:
  - 時刻: 左に固定。`filterType: 'dateSet'` に、相対プリセットとして今日・昨日(自作)・過去 7 日(自作)・過去 30 日を付けた。
  - レベル: `set` + `filterOptions` + `conditionalFormat.chips`(FATAL は `label`)。
  - サービス: `set` + 色を指定したチップ。
  - メッセージ: `autoHeight` + `flex`、`text` フィルター。traceId は `text` フィルター。
  - グリッド全体: `readOnly`、`density="compact"`、`height="100%"`、`autoHeight`、`find` + `onFindChange`、`scrollHint`、`showFilterChipBar`、`showCellOverflowTooltip`。
  - 展開行(`detailRow`): JSON のペイロード、スタックトレース、「この traceId で絞り込む」「JSON をコピー」「閉じる」。`onExpandedDetailRowKeysChange` も使った。
  - 右クリックメニュー: 行を JSON でコピー / メッセージをコピー / traceId で絞り込む / このサービスだけ / 詳細の開閉。
  - ハンドルで使ったもの: `applyState` / `getState` / `openFind` / `scrollToBottom` / `downloadCsv` など。
- **画面**: 上にツールバーを置いた。「ライブ(毎秒 50 行)」「末尾を追う」「ERROR 以上」「絞り込みを解除」「新しい順 / 古い順」「検索(n / N の表示)」「展開中の数」「CSV」。その下にグリッド。
  - 「末尾を追う」は `onScroll` と `.ssg-scroll-container` で末尾にいるかを調べ、`scrollToBottom()` を呼ぶ形で作った。
- **場所**: アプリは `/tmp/claude-0/-home-user-datasheet-grid/4235a129-3a13-5977-b0b9-8595e17bd91f/scratchpad/dogfood/G/src/App.tsx`(データは同じフォルダの `logs.ts`)。操作スクリプトは `/tmp/claude-0/-home-user-datasheet-grid/4235a129-3a13-5977-b0b9-8595e17bd91f/scratchpad/dogfood/G/pw/`、スクショは `/tmp/claude-0/-home-user-datasheet-grid/4235a129-3a13-5977-b0b9-8595e17bd91f/scratchpad/dogfood/G/shots/`。

### G-02 rows が毎秒変わると、100 万行ではセル内検索・グローバルフィルター・列フィルターの候補の収集が終わらない
- 重要度: **中** / 種類: 不具合(使いにくさ) / 主に本番で確認(検索とグローバルフィルターは dev でも) / 確度: 確実
- **再現**: 毎秒 50 行を足しながら、次を行う。
  - **セル内検索**: 20 秒間「検索中…」のまま。1 行目にある traceId(ヒットは 1 件)でも強調が出ず、`Enter` を押しても移動しない。追加を止めると 3.5 秒で「1 / 1」になる。
  - **グローバルフィルター**: 20 秒たっても絞り込まれない(本番 2 回とも)。dev では 20 秒間で長いタスクの合計が 26 秒になった。

- **原因の見立て**: 時間分割の処理が rows の変化で最初からやり直し、途中の結果を出さない。
- **回避策**:
  - 検索・絞り込みの間はアプリ側で追加を止める。
  - set / dateSet の列に `filterOptions` を固定で渡す(dateSet でもすぐ開くことを確認した)。
- **証拠**: すべて `/tmp/claude-0/-home-user-datasheet-grid/4235a129-3a13-5977-b0b9-8595e17bd91f/scratchpad/dogfood/G/pw/` にある。

### G-15 `onFindChange` で、ヒットを 10,000 件で打ち切ったことが分からない
- 重要度: 低 / 種類: 型 / dev / 確度: 確実
- **実際**: バーは「1 / 10000+」と出るのに、`onFindChange` は `matchCount: 10000` だけで、打ち切りを示す項目が無い。自作のツールバーでは「+」を出せない。

### G-16 セル内検索は、チップの `label` で変えた文字を対象にしない
- 重要度: 低 / 種類: ドキュメント / dev / 確度: 確実
- **実際**: 画面には「FATAL!」と出ているが、「FATAL!」で検索すると 0 件、「FATAL」だと 211 件。ドキュメントには明記されていない。

## 4. ピン留め行

**あった。**
- **固定したかった行**: 調査中のエラー行(ERROR / FATAL の 1 行)を表の上に固定して、時刻の近い前後のログをスクロールしながら比べたかった。
- **今の機能での代わり**:
  - 右クリック「この traceId で絞り込む」で関連する行だけに絞る。
  - 展開行でその行の詳細を開いたままにする。
  - 行番号を覚えて `scrollToRow` で戻る。
- ただし、100 万行のままでは展開行が描かれない(G-05)ので、絞り込みが前提になる。

## 5. 要望

- 組み込みの「末尾を追う」が欲しい(`followTail` のような prop、または `isAtBottom()`、`onScroll` に末尾かどうか)。圧縮スクロールのときも、末尾への追加で見ている行がずれないようにしてほしい(G-01 / G-08)。
- 時間分割の処理(検索・グローバルフィルター・候補の収集)を、追記のたびに最初からやり直さないでほしい。追記した分だけ足すか、途中の結果を出す(G-02)。
- 追記のときの並べ替えを差し込みにしてほしい(G-04)。
- dateSet で時刻の範囲や「過去 15 分 / 1 時間」を扱えるようにしてほしい(G-10)。
- 展開行が描けない行数のときは、トグルを出さないか理由を出してほしい(G-05)。
- 件数の表示は、既定で 3 桁区切りだと 100 万行で読みやすい(今は `localeText.rowCount` の関数で変えられる)。
