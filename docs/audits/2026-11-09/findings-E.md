## 3. 所見

### E-01 重要度 高 / 不具合: date 列が「年の無い日付」を 2001 年などとして受け取り、ありえない日付は翌月へ繰り越す

- 最小再現: `E/app/repro/date-paste.tsx`(date 列 1 つ)、`E/scripts/r3-date-paste.cjs`。セルを選んで、次の文字列を TSV で貼り付けます。
- 期待: docs の `api/column.mdx` の date の行には「年が 4 桁にならない文字列も解釈不可」(= 生の文字列のまま残す)とあります。ありえない日付も解釈できないものとして扱われるはずです。
- 実際:

| 貼り付けた文字列 | 書き込まれた値 |
| --- | --- |
| `11/1` | `2001-11-01` |
| `1/2` | `2001-01-02` |
| `12/31` | `2001-12-31` |
| `Nov 1` | `2001-11-01` |
| `0/5` | `2000-05-01` |
| `99/1` | `1999-01-01` |
| `2/30` | `2001-03-02` |
| `2026/2/30` | `2026-03-02` |
| `2026/02/29` | `2026-03-01` |
| `2026-02-30` | そのまま(実在しない ISO の日付を受け取る) |

- どれも検査の印は付かず、誤った年がそのまま書き込まれます。Excel から「11/1」を貼るのはよくある操作なので、気づかないうちにデータが壊れます。
- 証拠(原因の切り分け): core の `dist/logic/editorValues.js` は、`YYYY-MM-DD` に当たらないとき `new Date(s)` に任せ、年が 1000〜9999 の範囲かしか見ていません。Chromium(V8)は「11/1」を 2001 年と読みます。
- 同じ処理なので、フィルハンドルや custom の文字列の commit でも同じになるはずです(未確認)。
- 試したのは Chromium だけです。ほかのブラウザでは結果が変わる可能性があります。
- dev / 本番: 両方。確度: 確実。

### E-02 重要度 中 / ドキュメント・使いにくさ: Mantine `Modal` の中のグリッドで Esc を押すと Modal ごと閉じる

- 最小再現: `E/app/repro/mantine-modal.tsx`(Modal と全部入りのグリッド)、`E/scripts/r2-mantine-modal.cjs`、`E/scripts/14-modal.cjs`。
- Modal が閉じた操作: セル編集中、select / date エディタ、列メニューを開いた状態、列フィルターの入力欄、右クリックメニュー、検索バー、セルを選んでいるだけ。どれも Esc 1 回で Modal ごと閉じます。
- 閉じなかったのは、Mantine の Select を使った custom エディタだけでした。
- 期待: 編集の取り消しやメニューを閉じるだけで、Modal は残る。docs の installation には「Mantine — そのまま動きます」「ポップオーバーは Modal より上」とだけあります。
- 実際: グリッドは Esc で `preventDefault` しています(bubble 段階で `defaultPrevented: true` を確認)。しかし Mantine は window の capture 段階で閉じてしまいます。
- 回避: `closeOnEscape={false}` にすると、Esc で編集だけ取り消され、Modal は残ります(確認済み)。docs への注記を勧めます。
- 証拠: `E/shots/14-modal-*.png`。dev / 本番: 両方。確度: 確実。

### E-03 重要度 中 / 不具合(ドキュメントの不足も): custom エディタを開いたまま別のセルを押すと、エディタが残ってキー操作が効かなくなる

- 最小再現: `E/app/repro/custom-outside.tsx`、`E/scripts/r1-custom-outside.cjs`。docs の例と同じく、Enter / Esc だけを扱う `<input>` の custom エディタを使います。
  1. 行 2 を編集で開く。
  2. 行 5 のセルを押す。
- 期待: 組み込みのエディタと同じく、フォーカスアウトで確定して閉じる。せめて、Esc や矢印キーが効く状態に戻る。

  - アクティブセルは行 5 へ移りますが、行 2 のエディタは開いたままです。
  - フォーカスはグリッドにあるのに、矢印・文字の入力・Esc がどれも効きません。
  - 別のセルをダブルクリックするまで抜け出せません。
  - docs には「フォーカス管理は利用側の責務」とあるだけで、onBlur で `ctx.commit` を呼ぶ必要があることは書かれていません。
- 回避: 商品マスタでは `onBlur={() => ctx.commit(value)}` と Tab の処理を足して解消しました。

## 5. 要望

1. **date 列**(E-01): 年の無い文字列とありえない日付は、docs のとおり解釈しないでほしいです。加えて、`2026年11月1日`・全角・和暦(`R8/11/1`)を読むか、列ごとに日付の読み方を差し込める手段が欲しいです(今はどれも生の文字列のまま残ります)。
2. **Modal の中での使い方**(E-02): docs に `closeOnEscape={false}` の注記を入れてほしいです。グリッドが処理した Esc を外へ伝えない仕組みもあると助かります。
3. **custom エディタ**(E-03): フォーカスアウトでグリッド側が確定するか、そうでないなら docs の例に `onBlur` を入れてほしいです。
4. **行ドラッグ**(E-06 / E-07): 落とせる先を決める関数(例: `canDropRow`)と、ゴーストの文字を決める関数が欲しいです。
5. **select エディタ**(E-08): 選択肢が多い列のために、部分一致の検索(IME の入力を含む)が欲しいです。
6. **選択範囲の集計**(E-09): 列ごとに集計から外す指定が欲しいです。
7. **ドキュメント**: 「`/lite` と全部入りを同じページで使うと約 +32KB」の目安を、lite のガイドの注意に添えてほしいです。今は Turbopack の数字しかありません。
8. **右クリックメニュー**(E-11): Shift+F10 とアプリケーションキーで開けるようにしてほしいです。
