## いつも行う確認

- ゲート(CLAUDE.md の表): tsc(build / test)・eslint・vitest・size・build・examples・types。PR ごとに全部。
- 監査ハーネス(`audit/harness/`): 機能を変えたら関係するスクリプトを、リリース前は全部を 3 ブラウザで(Chromium は Playwright、Firefox は geckodriver、WebKit は WebKitGTK。クラウドでの動かし方は `audit/harness/README.md` の「他のブラウザで回す」)。
- 公開の後: npm のレジストリで両パッケージの latest と同じ版の固定を見る、pack した tarball と手元のビルドが同じか比べる、GitHub Release ができたか、`examples/basic` を公開版で新しく入れてビルドとブラウザで確かめる。
- 大きな変更の後: 別視点のレビュー(サブエージェントにコードだけを渡す)と、直した版でアプリを作り直す確認。
