## ことばで絞り込み(`/ai` サブパス)

`@ishibashi0112/spreadsheet-grid/ai` の `GridAskBar` をグリッドの上に置くと、利用者が「東京の在庫が 10 個以下を高い順に」のように書いた文を AI に頼んで、グリッドのフィルター・並び・グローバル検索・列の表示へ反映できる(0.57.0 で追加)。グリッドは AI を呼ばない。利用側が渡す `ask`(自分のサーバー → 好きな AI)で聞くので、AI の種類は問わず、API キーはサーバーに置ける。全部入り・`/lite` とは別の入口で、使うときだけバンドルに入る(全部入り・`/lite` の JS の大きさは変わらない。`/ai` は約 13.8KB gzip)。

```tsx
import { useRef } from 'react';
import { SpreadsheetGrid, type SpreadsheetGridHandle } from '@ishibashi0112/spreadsheet-grid';
import { GridAskBar, type GridAsk } from '@ishibashi0112/spreadsheet-grid/ai';
import '@ishibashi0112/spreadsheet-grid/style.css';

// 自分のサーバーを通して AI に聞く(API キーをブラウザに置かない)
const ask: GridAsk = async (request, { signal }) => {
  const res = await fetch('/api/grid-ask', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(request),
    signal,
  });
  if (!res.ok) throw new Error(`grid-ask: ${res.status}`);
  return res.json();
};

export function Inventory() {
  const gridRef = useRef<SpreadsheetGridHandle<Row>>(null);
  return (
    <>
      <GridAskBar
        grid={gridRef}
        columns={columns}
        ask={ask}
        examples={['東京の在庫が 10 個以下', '今月入荷した家電を高い順に']}
      />
      <SpreadsheetGrid ref={gridRef} columns={columns} rows={rows} />
    </>
  );
}
```

サーバー側の例(Next.js の Route Handler と Claude)。答えの形は `request.schema`(JSON Schema)で決まっているので、構造化出力にそのまま渡す:

```ts
// app/api/grid-ask/route.ts
import Anthropic from '@anthropic-ai/sdk';

const anthropic = new Anthropic(); // ANTHROPIC_API_KEY はサーバーの環境変数

export async function POST(req: Request) {
  // ここでログインしているか・呼ぶ回数を確かめる
  const { system, prompt, schema } = await req.json();
  const message = await anthropic.messages.create({
    model: 'claude-haiku-5-5', // 小さく速いモデルで足りる
    max_tokens: 4096, // 考える分(thinking)も含む上限
    system,
    messages: [{ role: 'user', content: prompt }],
    // effort: 'low' で考える量を減らして速く答えさせる。format で答えを schema の形に固定する。
    output_config: { effort: 'low', format: { type: 'json_schema', schema } },
  });
  // 答えの文字列をそのまま返す(読んで検査するのはバー側。途中で切れた答えも「読めませんでした」になる)。
  const text = message.content.find((block) => block.type === 'text');
  return Response.json(text ? text.text : null);
}
```

- ほかの AI でも、画面側(`ask`)はそのままで、サーバーで `system` / `prompt` / `schema` を渡す先が変わるだけ。各社のコード全体はガイド「[ことばで絞り込み(AI)](/docs/guides/ai-filter)」。
  - **OpenAI**(Responses API): `instructions` に `system`、`input` に `prompt`、`text: { format: { type: 'json_schema', name: 'grid_view', schema, strict: true } }`。答えは `response.output_text`。
  - **Gemini**(`@google/genai` の `models.generateContent`): `contents` に `prompt`、`config` に `{ systemInstruction: system, responseMimeType: 'application/json', responseJsonSchema: schema }`。答えは `response.text`。
  - **Vercel AI SDK**(AI Gateway): `generateText({ model: 'anthropic/claude-haiku-5.5', system, prompt, output: Output.object({ schema: jsonSchema(schema) }) })` の `output` を返す。`model` の文字列を替えるだけで、AI Gateway 経由でほかの会社の AI に切り替わる。
- `schema` は Claude / OpenAI(strict)/ Gemini の構造化出力の制約(すべての欄が必須・`additionalProperties: false`・null を許す欄は `anyOf`)に合わせてある。構造化出力の無い AI では、`prompt` の後に「この JSON Schema に合う JSON だけを返す」と書き足し、答えを JSON の文字列のまま返してもよい(前後の文や ```` ```json ```` の囲みは外して読む)。
- 1 回の頼みは入力 千〜数千トークン・出力 数百トークン程度(列の数と候補の数による)。

### `GridAskBar` の props(`GridAskBarProps<T>`)

| prop | 型 | 説明 |
| --- | --- | --- |
| `grid` | `{ current: { getState, applyState } \| null }` | `SpreadsheetGrid` の ref。`getState()` で今の状態を読み、`applyState()` で反映する。 |
| `columns` | `readonly GridColumn<T>[]` | グリッドと同じ列定義。AI に見せるのは `key` / `title` / `filterType` / 候補(`filterOptions`、select エディタの静的な選択肢)/ dateSet のプリセットだけ。 |
| `ask` | `GridAsk` = `(request, { signal }) => Promise<unknown> \| unknown` | AI に聞く関数。`request` は `{ system, prompt, schema, text }`(`text` は利用者の文そのもの)。答えはオブジェクトか JSON の文字列。`signal` は「止める」/ Esc / アンマウントで abort される(聞いている間の次の頼みは受け付けない)。 |
| `examples` | `readonly string[]` | 入力欄の下に出す例の文。押すとその文で聞く。 |
| `columnHints` | `Record<string, string \| false>` | 列ごとの補足(単位や値の書き方。例 `{ stock: '個', price: '円・税抜' }`)。`false` でその列を AI に見せない(その列の条件も変えない)。列に無いキー(打ち間違い)は効かないので、開発時に console へ警告する。 |
| `allowFilter` | `boolean` | 列の条件(フィルター)を変えてよいか。既定 `true`(グリッドの `enableColumnFilter` を `false` にしているときは `false` にする。表の見出しから外せない条件を入れないため)。 |
| `allowSort` | `boolean` | 並びを変えてよいか。既定 `true`(グリッドの `enableSorting` を `false` にしているときは `false` にする)。 |
| `allowSearch` | `boolean` | グローバル検索の文字を変えてよいか。既定 `true`(`enableGlobalFilter` を `false` にしているときは `false` にする)。 |
| `allowColumnVisibility` | `boolean` | 列を隠す・見せるのを許す。既定 `false`(列の表示の反映にはグリッドの `onColumnsChange` が要るので、渡しているときに付ける)。 |
| `onApply` | `(event: { text, state, dropped, unsupported }) => void` | 反映したあとに呼ぶ(ログなどに)。表を変えなかった答え(使えない部分だけ / 今と同じ条件)と、読めない答えでは呼ばない(`onError` も `ask` の例外だけ)。AI の答えの質(断った・使えなかった部分)をすべて記録したいときは、`ask` の中(自分のサーバー)で記録する。 |
| `onError` | `(error: unknown) => void` | `ask` が失敗(throw / reject)したときに呼ぶ。止めたときは呼ばない。 |
| `placeholder` / `label` | `string` | 入力欄のプレースホルダーと、読み上げ用のラベル(既定は `localeText` の `placeholder` / `label` = 「ことばで絞り込み」)。 |
| `localeText` | `Partial<GridAskLocaleText>` | バーの文言(既定は日本語)。変えたいキーだけを渡す。英語は入口 `/locales/en` の `gridAskLocaleTextEn`。キーは「AI バーの文言(`localeText`)」。 |
| `className` | `string` | バーの root(`.ssg-ask`)に足すクラス。 |
| `theme` | `'light' \| 'dark' \| 'auto' \| 'class'` | 配色。既定 `'light'`。グリッドの `theme` と同じ値を渡す。 |

### AI が変えられるもの

- **列フィルター**: AI が入れられる条件は、その列のフィルター画面で手で入れられる条件と同じ(列の `filterType` で決まる)。`filterType` の無い列と `'custom'` の列は絞り込めない(並び替えと表示の切り替えだけ)。数や日付の列は `filterType` を付けておくと「以上」「範囲」「今月」なども使える。

| 列の `filterType` | AI が入れられる条件 |
| --- | --- |
| `text` | 含む |
| `textSet` | 含む / 等しい / で始まる / で終わる / 空白 / 空白でない と、値の選択(含める・除く) |
| `number` | = / ≠ / > / ≥ / < / ≤ / 範囲 / 空白 / 空白でない |
| `numberSet` | `number` と同じ条件と、値の選択 |
| `date` | 含む(日付を文字として。AI にはセルの書き方で書くよう伝えるので、書き方は `columnHints` で補う) |
| `dateSet` | 範囲 / 以降 / 以前 / 等しい / 等しくない / プリセット(`dateFilterPresets` の今日・今月など)/ 空白 / 空白でない と、値の選択 |
| `select` | 1 つの値に一致 |
| `set` | 値の選択(含める・除く) |
| `auto` | 適用中の条件の種類 → editor が number なら `numberSet`・date なら `dateSet` → それ以外は `text`(含む だけ)。行のデータからは推定しない |

- **並び**(複数の列も)、**グローバル検索の文字**、**列を隠す・見せる**(`allowColumnVisibility` のときだけ。すべての列は隠さない)。
- 行のグループ分け・列の順番と固定・列幅は変えない。セルの値や行は変えない。
- **置き換えと足し算**: AI は「今の条件を空にしてから入れる(replace)」か「今の条件に足す・直す(refine。「さらに」「〜だけ」など)」を選ぶ。今の条件は毎回 AI に渡すので、「さらに 1 万円以上」のような続けての頼みができる(前の文は覚えていない)。replace でも、AI が変えられない条件(AI に見せていない列の条件と並び、絞り込めない列のフィルター)と隠した列はそのまま(AI に見せていない列の並びは、AI の並びが今と同じなら元の位置のまま、変わったら AI の並びの後ろ)。refine で「条件 + 値の選択」の列(`numberSet` / `textSet` / `dateSet`)の片方だけを変えたときは、もう片方は残す。
- **値の選択**: AI は値の選択を毎回まるごと書く(refine で 1 つ足すときも今の値を書き直す)。`""` は空白のセル(フィルター画面の「(空白)」)。今の選択にある値は書かれたまま使う(言い直しで `'100.00'` を `'100'` のように書き換えない)。今の選択が 500 件を超えるときは先頭の 500 件だけを AI に渡し、残りは refine で同じ条件(含める / 除く)のまま書き直したとき(replace では渡した 500 件をすべて書き直したとき)も残す。選択を入れ替えるときは、AI が同じ答えの中で先にその列を外す(`clear`)。AI が選んだ値が 1 つも無いときは、残りだけの選択にせず今の選択のまま。値の並びだけが違う書き直しでは変えない。

### 送るものと検査

- **送るもの**: 列の `key` / `title` / 使える条件 / 列定義にある候補(最大 50 件を並べ、残りは件数だけ)/ `columnHints` / 今の条件(AI が変えられる列の分。値の選択は 1 列 500 件まで)/ 今日の日付 / 利用者の文。**行のデータは送らない**(列定義に候補が無い列の「値の選択」は、AI が文から書いた値をそのまま使う)。
- **答えはすべて検査する**: 表への指示に見えない答え(サーバーのエラーの `{ error }` など。`mode` も `filters` も無い答え)は表を変えずに知らせる(`mode` があって `filters` だけが無い答えは条件なしとして読む)。無い列・その列で使えない条件・候補に無い値・数や日付として読めない値・長すぎる値(条件と検索の文字は 200 字、選ぶ値は 1 つ 1000 字・1 列 1000 件まで。切り詰めずに捨てる)は捨て、何を捨てたかを「使えなかった部分」に出す(20 件まで。文言は `localeText`、既定は日本語)。列は `key` で引き、無ければ見出し(同じ見出しが 1 列だけのとき)で引く。候補は値・表示名のどちらで答えても値へ直す(select の値 `''` は「すべて」と同じなので選ばない)。数は全角や 3 桁区切りも読み、日付は `YYYY-MM-DD` へ揃える。範囲の逆転は入れ替える。並びの向きは大文字や `ascending` / `descending` も読む(refine で書いてきた並びが 1 つも使えないときは今の並びのまま)。形の読めない条件・列の指定・検索の文字・並び(配列でない `sort` など。1.0.2 から)も「使えなかった部分」に出す。replace で書いてきた条件・並び・検索・列の表示がどれも使えなかったときは、表を空にせず今のままにする(「変える条件はありませんでした」。1.0.2 から。1.0.1 までは今の条件が消えて全件になった。何も書かずに空を返した答えはこれまでどおり空にする)。AI が「できなかった」と書いてきた文(`unsupported`)は「AI から: …」として出す(前後の空白を除いて 300 字まで。超えた分は切る)。列が 100 を超える表では、`schema` で列を enum にしない(enum の数に上限がある AI があるため。無い列は検査で捨てる)。
- **反映と元に戻す**: 答えはすぐ反映し、反映した状態の条件をチップ(列フィルター → 並び → 検索 → 隠した列)で見せる。チップの select / set の値は表示名(`filterOptions` / select エディタの選択肢。無ければ値のまま)で、数の条件は列の `valueFormatter` で書く(グリッドのチップバー・フィルターの管理と同じ)。チップの × でその条件だけ外せる。「元に戻す」で頼む前の見え方(フィルター・並び・検索・隠した列)へ戻す(列幅・列の順番・固定はそのまま)。反映したあとに表を手で変えたときは(チップバーの ×・グローバル検索・`applyState` など。クリック / キー操作の後と 1 秒ごとに `getState()` で確かめる)、チップと「元に戻す」を下げて「表の条件が変わったので…」と知らせる(押してから知らせるのではない。列の表示を AI に任せていないときは、手で隠した列は比べず、元に戻すでも変えない)。列の表示が変わらないときは `applyState` に `columns` を渡さない(列定義を `onColumnsChange` で書き直さない)。列の表示を変えたとき(隠す・見せる・元に戻す)は `applyState` の規則どおり、`onColumnsChange` に渡る配列が固定列ごと(左固定 → 中央 → 右固定)に並べ直される(画面の列の並びは同じ)。`columns` の配列の途中に固定した列がある表では、後でその列の固定を外すと配列の先頭(固定していた位置)に残るので、固定を外したときの位置を決めておきたいときは、固定する列を配列の先頭(右固定は末尾)に書いておく。
- **入力**: Enter で送る。日本語の変換を確定する Enter では送らない。答えを読めたら入力欄を空にする(考えている間に書き換えていれば残す。失敗したときは直して送れるよう残す)。考えている間は「止める」か Esc で取り消せる(届いた答えは捨てる)。Esc はフォーカスがバーの中か、どこにも無いときに効く(表やほかの部品の Esc は取らない。日本語の変換中の Esc では止めない。バーを shadow root の中に置いても効く)。「聞く」「止める」のダブルクリックの 2 回目は無視する(止めたつもりで送り直したり、送ってすぐ止めたりしない)。考えている間、例のボタンは `aria-disabled`。失敗したときは表を変えずに「もう一度」を出す(失敗した文を送り直す)。表(`grid` の ref)がまだ無いときは知らせる。聞いている間に props(列・`allow*`・`onApply` など)が変わったら、答えは変わったあとの設定で読む。押したボタン(チップの × / 元に戻す / 閉じる)が消えたら、フォーカスは次のチップか入力欄へ移す。チップと例は全文を `title` に持つ(狭い幅では省略表示)。
- **見た目**: 色はグリッドと同じトークン(`--ssg-*`)で決まる。バーはグリッドの外にあるので、トークンを `.ssg-root { … }` で上書きしているときは `.ssg-root, .ssg-ask { … }` のように `.ssg-ask` も並べる。`themes/*.css` はバーにも効く。クラスは `.ssg-ask` / `.ssg-ask-form` / `.ssg-ask-input` / `.ssg-ask-examples` / `.ssg-ask-chips` / `.ssg-ask-chip` / `.ssg-ask-note`(公開契約。ほかの `ssg-ask-*` は内部)。

### AI バーの文言(`localeText`)

`GridAskBar` / `useGridAsk` の `localeText` で、バーの文言(入力欄・ボタン・知らせ・反映した条件のチップ・「使えなかった部分」の理由)を変えられます。既定は日本語です。英語はグリッドと同じ入口 `@ishibashi0112/spreadsheet-grid/locales/en` の `gridAskLocaleTextEn` です。条件の要約(`conditionContains` など)はグリッドの `localeText` と同じキーです。AI に送る指示(`system` / `prompt` の決まった文)は言語によらず英語です(利用者の文はそのまま送るので、どの言語で聞いてもよい)。列の見出し・候補の値・日付の期間のプリセットの名前は画面と同じ文字を送ります(組み込みのプリセットは `localeText` の `datePresetToday` などなので、英語なら `Today`)。 `localeText` を途中で変えたときは、出ている知らせ・エラー・反映した条件のチップは、次に頼んだときから新しい文言になります。

```tsx
import { GridAskBar } from '@ishibashi0112/spreadsheet-grid/ai';
import { gridAskLocaleTextEn, localeTextEn } from '@ishibashi0112/spreadsheet-grid/locales/en';

<GridAskBar grid={gridRef} columns={columns} ask={ask} localeText={gridAskLocaleTextEn} />
<SpreadsheetGrid ref={gridRef} columns={columns} rows={rows} localeText={localeTextEn} />
```

core の関数(`createGridAskRequest` / `readGridAskAnswer` / `describeGridAskView`)にも `options.localeText` で渡せます(「使えなかった部分」の理由とチップの文言)。

### 自前の見た目で作る(`useGridAsk`)と core の関数

`useGridAsk(options)` は `GridAskBar` の状態とふるまいだけを返す(`options` は `GridAskBar` の props のうち `examples` / `placeholder` / `label` / `className` / `theme` 以外)。

| 返り値 | 説明 |
| --- | --- |
| `status` | `'idle' \| 'asking'` |
| `error` / `notice` | 失敗の文 / 元に戻せなかったときなどの知らせ(無ければ `null`) |
| `session` | 最後の頼みの結果 `{ phase: 'applied' \| 'unchanged' \| 'undone' \| 'changed', text, items, dropped, unsupported }`(`items` はチップ `{ id, label, text }[]`。`'changed'` は反映したあと表が手で変わったとき。チップは古いので外す・元に戻すはできず、`notice` に知らせが入る。`'undone'` / `'changed'` の `items` は元に戻す前 / 表が変わる前のチップで、今の表の条件ではない。自作の画面で今の条件として出さない) |
| `submit(text)` / `cancel()` / `undo()` / `remove(id)` / `dismiss()` | 聞いて反映する / 止める / 元に戻す / チップを外す / 結果を閉じる。`submit` は答えを読めたら(反映した / 変える条件が無かった)`true`、失敗・止めた・聞かなかったときは `false` で終わる(送った後に入力欄を空にするかの判断に) |

自分の UI を作るときは、`GridAskBar` がしている次のことを自分で書く:

- **二重の送信**: 聞いている間の `submit` は何もせず `false` を返すので、二重には送られない。「聞く」と「止める」を同じボタンにするときは、ダブルクリックの 2 回目(`event.detail > 1`)を無視する(止めた直後に同じ文を送り直さないため)。
- **IME**: 変換を確定する Enter で送らない(`event.nativeEvent.isComposing` か `event.keyCode === 229` の Enter は `preventDefault()`。Safari は確定の keydown が `isComposing: false` / `keyCode: 229` で届く)。
- **Esc**: 聞いている間の `Esc` で `cancel()` する(バーは、フォーカスがバーの中にあるか、どこにも無いときだけ止める。変換中の `Esc` は除く)。
- **もう一度**: 失敗したとき(`error`)に送り直すなら、送った文を自分で持っておいて `submit` する(`error` は失敗の文だけで、送った文は持たない)。
- **入力欄**: 答えを読めたら(`submit` が `true`)入力欄を空にする。ただし考えている間に書き換えていたら残す(送った文と今の入力欄が同じときだけ空にする。バーと同じ)。失敗したときは残す(直して送れるように)。

頼みの組み立てと答えの検査は React に依存しない core の関数(`@ishibashi0112/spreadsheet-grid-core` の入口と、`/ai` から再エクスポート)。サーバー側で頼みを組み立て直したり、ほかのフレームワークで使える。

| 関数 | 説明 |
| --- | --- |
| `createGridAskRequest(text, state, options): GridAskRequest` | 利用者の文と今の状態(`getState()`)から頼み `{ system, prompt, schema, text }` を作る。`options` は `{ columns, columnHints?, allowFilter?, allowSort?, allowSearch?, allowColumnVisibility?, now?, localeText? }`。 |
| `readGridAskAnswer(answer, state, options): GridAskResult` | 答えを検査して `{ ok: true, state, changed, dropped, unsupported }`(`state` は `applyState` に渡せる状態)か `{ ok: false, message }` を返す。 |
| `gridAskSystemPrompt` | `system` の文(いつも同じ)。 |
| `describeGridAskView(state, options)` / `removeGridAskItem(state, id)` | 状態のチップの一覧 / チップ 1 件を外した状態。 |
| `isGridAskColumnsChanged(a, b)` / `isSameGridAskView(a, b)` | 隠した列が 2 つの状態で違うか / 見え方(フィルター・並び・検索・隠した列)が同じか(列幅・列の順番・固定は見ない)。反映するときと、反映したあと表が手で変わったかの判定に使う(下の例)。 |
| 型 `GridAskAnswer` / `GridAskFilter` / `GridAskSort` / `GridAskOp` | 答えの形(`mode: 'replace' \| 'refine'`、`filters: { column, op, value, values, to }[]`、`sort`、`search`、`hide`、`show`、`unsupported`)。 |

core の関数で反映するときは、`readGridAskAnswer` の `state` をそのまま `applyState` に渡さず、隠した列が変わらないときは `columns` を外して渡す(`state.columns` は答えを読んだときの `getState()` のものなので、そのまま渡すと列定義を `onColumnsChange` で書き直し、聞いている間に手で隠した列が戻ることがある。`applyState` は渡さなかった部分を今のまま残す)。

```ts
import { createGridAskRequest, readGridAskAnswer, isGridAskColumnsChanged } from '@ishibashi0112/spreadsheet-grid/ai';

const controller = new AbortController(); // 止めるときは controller.abort()
const answer = await ask(createGridAskRequest(text, grid.getState(), options), { signal: controller.signal });
const now = grid.getState(); // 答えが届いた時点の状態で読む
const result = readGridAskAnswer(answer, now, options);
if (result.ok && result.changed) {
  grid.applyState(isGridAskColumnsChanged(now, result.state) ? result.state : { ...result.state, columns: undefined });
}
```
