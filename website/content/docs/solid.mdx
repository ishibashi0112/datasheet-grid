**`@ishibashi0112/spreadsheet-grid-solid`** は Solid 2.0 向けのグリッドです。React 版と同じ props・列の定義・命令的なハンドル・CSS・見た目で、同じフレームワークに依らないコア(`@ishibashi0112/spreadsheet-grid-core`)の上に作っています。このサイトのガイドと API リファレンスは React 版向けに書いていますが、props とメソッドは同じなので、そのまま読み替えて使えます。このページには Solid 版だけのことをまとめます。

版は React 版・コアとは別(0.x)です([版と変更履歴](#版と変更履歴))。

## インストール

```sh tab="npm"
npm install @ishibashi0112/spreadsheet-grid-solid
```

```sh tab="pnpm"
pnpm add @ishibashi0112/spreadsheet-grid-solid
```

```sh tab="yarn"
yarn add @ishibashi0112/spreadsheet-grid-solid
```

**solid-js** と **@solidjs/web** の `^2.0.0` が peer dependencies です。コア(`@ishibashi0112/spreadsheet-grid-core`)と `@tanstack/virtual-core` は自動で入ります。対応ブラウザは React 版と同じく Chrome / Edge 111 以降、Firefox 121 以降、Safari 16.4 以降です。

CSS はアプリのエントリなどで 1 回だけ読み込みます。

```ts
import '@ishibashi0112/spreadsheet-grid-solid/style.css'
```

`style.layer.css` とデザインシステムのテーマ(`themes/astryx.css` / `themes/mantine.css` / `themes/heroui.css` / `themes/shadcn.css`)は React 版と同じファイルです([インストール](/docs/installation)・[デザインシステムに合わせる](/docs/guides/design-systems))。

### バンドラの設定

パッケージは Solid のライブラリの慣例どおり、`solid` 条件で JSX のままのソースを渡し、利用側のバンドラが自分の Solid の設定(DOM / SSR・開発 / 本番)でコンパイルします。Vite では `@solidjs/vite-plugin` 3(Vite 8 以上)を使ってください。`solid` 条件の無いツールは DOM 向けにコンパイル済みのビルド(ESM だけ)を読みます。

Node の中(Vitest と jsdom のテストなど)では `solid` か `browser` の条件で解決してください(`@solidjs/vite-plugin` が付けます)。Node の既定の条件では `@solidjs/web` がサーバー向けのビルドになり、「Client-only API called on the server side」で止まります。

## 最小の例

`rows={rows()}` のように signal を呼んで渡し、編集は `onRowsChange` で受け取って signal へ戻します。

```tsx
import { createSignal } from 'solid-js'
import { SpreadsheetGrid, type GridColumn } from '@ishibashi0112/spreadsheet-grid-solid'
import '@ishibashi0112/spreadsheet-grid-solid/style.css'

type Row = { id: number; name: string; qty: number }

const columns: GridColumn<Row>[] = [
  { key: 'name', title: 'Name', width: 200, editable: true, filterType: 'text' },
  { key: 'qty',  title: 'Qty',  width: 120, editable: true, filterType: 'number' },
]

export function Example() {
  const [rows, setRows] = createSignal<Row[]>([
    { id: 1, name: 'Apple',  qty: 3 },
    { id: 2, name: 'Banana', qty: 5 },
  ])

  return (
    <SpreadsheetGrid
      rows={rows()}
      columns={columns}
      onRowsChange={(next) => setRows(next)}
      rowKeyGetter={(row) => row.id}
    />
  )
}
```

英語の文言は `@ishibashi0112/spreadsheet-grid-solid/locales/en` の `localeTextEn` を `localeText` に渡します([英語と文言](/docs/guides/localization))。

## 機能を選んで組み込む

`SpreadsheetGrid` は全機能入りです(初期読み込みの JS が約 166KB gzip。列フィルターのポップオーバーとツールパネルの約 16KB は後から読みます)。`createSpreadsheetGrid` では渡した機能だけを入れたグリッドを作れ、渡さなかった機能はバンドルに入りません(機能なしで約 94KB、プリセット `standardFeatures` で約 121KB)。React 版と違い、機能の部品も同じ入口から import します(`/lite` はありません)。機能の名前と中身は[バンドルを小さくする](/docs/guides/lite)のとおりです(部品の名前も同じ)。

```tsx
import { createSpreadsheetGrid, standardFeatures, serverSideFeature } from '@ishibashi0112/spreadsheet-grid-solid'

// コンポーネントの中ではなく、モジュールの先頭で 1 回だけ作る
const Grid = createSpreadsheetGrid({ features: { ...standardFeatures, serverSide: serverSideFeature } })
```

## React 版との違い

- **`ref` は Solid の DOM の ref と同じです。** `let grid!: SpreadsheetGridHandle<Row>` と `ref={grid}`、または `ref={(handle) => (grid = handle)}` で、同じメソッドを持つハンドルを受け取れます(React の ref オブジェクトはありません)。ハンドルは利用側の部品の最初の `createEffect` と `onSettled` より前に入るので、そこで呼べます(保存した状態を戻す、末尾へスクロールする など)。`<Loading>` の中では最初の行が届くまでグリッドを描かず、それまでに呼んだ状態を変えるメソッドは何もしません(開発時に 1 回知らせます)。最初の状態は `initialState` で渡すか、行を読む effect(`createEffect(() => rows().length, …)`)から呼んでください。グリッドを外した後(`<Show>` で隠したときなど)も変数に残ったハンドルは、状態を変えるメソッドは何もせず(開発時に 1 回知らせます)、読むメソッドは外したときの値を返します(`onCleanup` で `grid.getState()` を保存できます。`getScrollPosition()` は `null`、`isAtBottom()` は `false`)。
- **描く関数は必要なときだけ呼びます。** `renderCell` と `renderHeader` は列が変わったとき、バーの関数は関数が変わったときに呼び直します(React 版のように更新のたびには呼びません)。文脈の値(`row` / `value` / `rowIndex` / `isActive`、バーの文脈と、その `derivedSummary` の各項目など)は読んだときに引くので、JSX の中で読めばその式だけが追従します。セルの中の入力欄で打つたびに `ctx.setValue` しても、入力欄はそのままでフォーカスも外れません(1.4.0 から。それまでは行が変わるたびにセルの中身を作り直していました)。関数の本体で読むと(引数の分割代入も)、その値が変わったときに中身を作り直します(バーの入力欄なら、フォーカスと打ちかけの文字が消えます)。自分の部品の本体の一番上で読むと(`renderCell={(ctx) => <MyCell ctx={ctx} />}` で `MyCell` の中の `const v = props.ctx.value`)、その後の変化に追従しません(開発時に Solid が `STRICT_READ_UNTRACKED` を出します)。そこでも JSX の中で読んでください。グリッドの外の signal を `renderCell` の本体で読むと、変わるたびに見えているすべてのセルの中身を作り直します。JSX の中で読むか、行のキーごとの memo を通してください。
- **ことばで絞り込み(`/ai`)。** `GridAskBar` と `createGridAsk`(React 版の `useGridAsk`。Solid の慣例で `create…` の名前)は `@ishibashi0112/spreadsheet-grid-solid/ai` から import します(約 15KB gzip。グリッドのバンドルとは別)。グリッドはハンドルを返す関数 `grid={() => grid}`(`let grid!` と `ref={grid}`)か signal(`ref={setGrid}` と `grid={grid}`)で渡します(ref オブジェクトはありません)。そのほか(利用側の `ask`・答えの形・`/locales/en` の `gridAskLocaleTextEn`)は React 版と同じです([ことばで絞り込み](/docs/guides/ai-filter))。
- そのほか(props・列の定義・ハンドルのメソッド・通知・CSS のクラスとトークン)は [API リファレンス](/docs/api/props)と同じです。

## Solid で気をつけること

- **`rows` は signal でも store でも持てます。** `onRowsChange` は編集のたびに新しい配列を返します(React 版と同じ約束)。signal なら `setRows(next)` でそのまま戻します。`createStore` なら `rows={state.rows}` で渡し、`setState((s) => { s.rows = next })` か `setState((s) => { reconcile(next, 'id')(s.rows) })` で戻すと、signal のときと同じく元に戻す / やり直しが効きます(1.4.0 から)。store の中を直接変えたとき(`s.rows[0].name = …` / `push` / `splice`)もグリッドに映り、React 版で親が rows を差し替えたときと同じく元に戻すの履歴は消えます。store は中の変化に気づくため行ごとに追うので、行が多いと編集のたびに時間がかかります(10 万行で 1 回 0.1 秒ほど)。5 万行ほどより多い表は signal で持ってください(開発時に 1 回勧めます)。
- **書き込みはマイクロタスクで反映されます。** `setRows(...)` の後、グリッドが新しい行を見るのは次の反映のときです。足したばかりの行をすぐ使う(`getViewRowIndex(key)` → `startEditing(...)`)ときは、先に `solid-js` の `flush()` を呼んでください(React 版のドキュメントの `flushSync` と同じ)。
- **`action` で保存する。** グリッドの通知の中で `action` を始めてかまいません(`onRowsChange={(next) => save(next)}` で action の中で `createOptimistic` に書く、または `setRows(next)` の後に `save(next)`)。グリッドは自分の書き込みを利用者の action に入れないので、保存の間もエディタは閉じ、続けた編集はその行に入ります(React 版の `startTransition` と同じ)。保存先(プロジェクトの ID など)は、先に別の値へ変わっていることがある props ではなく、受け取った行から取ってください。保存した行を `refresh()` で取り直すと、`rows` が外から差し替わるので、元に戻すの履歴は消えます(React 版と同じ)。
- **非同期の行。** 非同期の `createMemo` / `createSignal(async)` の行は `<Loading>` の中で使えます(最初の行が届くまでは fallback)。取り直しの間は前の行のまま操作できるので、待っていることは `isPending(() => rows())` で出してください。`<Loading on={...}>` では取り直しの間 fallback がグリッドに替わります(グリッドの状態は残り、行が届くと戻ります)。替わるときに編集中の値は確定し、`onRowsChange` には前の行が渡ります。取り直しの失敗は利用側の `<Errored>` が受けます。`createDeferred` で読んだ行は、保存の `refresh()` の取り直しの間は元の値を出します(`createDeferred` の意味どおり)。非同期の `createMemo` なら保存した値のままです。
- **描いた後の通知。** React 版が描いた後の effect で呼ぶ通知(`onActiveCellChange` / `onStateChange` / `onFiltersChange` / `onSortChange` / `onExpandedDetailRowKeysChange`、選んだ行を消して選択から外したときの `onRowSelectionChange`)は、その変化を反映し終えた直後(次のマイクロタスク)に呼び、グリッドを外した後には呼びません。テストでは `flush()` の後に `await Promise.resolve()` で 1 回待ってから確かめてください。
- **テスト(Vitest + jsdom)。** Vitest の設定に `@solidjs/vite-plugin` を入れてください。プラグイン無しなら `browser` を `resolve.conditions` / `ssr.resolve.conditions` / `ssr.resolve.externalConditions` の 3 か所すべてに書きます。`@solidjs/testing-library` は Solid 2 向けの版(1.0 の候補版)を使い、jsdom にはレイアウトが無いので `@ishibashi0112/spreadsheet-grid-solid/testing` の `installJsdomLayoutStubs` を呼びます。signal を変えた・イベントを送った後は、DOM を見る前に `flush()` を呼びます([テスト](/docs/guides/testing)の React 版の `act()` の代わり。描いた後の通知は、さらに `await Promise.resolve()` で 1 回待ってから)。
- **SSR。** 今の SolidStart は Solid 1 だけに対応しています。Solid 2 では Vite の SSR と `@solidjs/vite-plugin`(`ssr: true`)で、サーバーは `renderToString` か `renderToStream` と `generateHydrationScript`、クライアントは `hydrate` を使います(`@solidjs/router` 2 は `@solidjs/web` の `createRequestEvent` と `@solidjs/web/storage` の `provideRequestEvent` も要ります)。サーバーで描くのはグリッドの骨組み(見出し・上下のバーの絞り込み / 並び替えの表示)だけで、行・固定列のセル・件数・合計はハイドレーションの後に描きます。サーバーとブラウザでタイムゾーンや今日が違っても(日付の条件・Date の値)、サーバーの行がページに残りません(Solid のハイドレーションはクライアントで違う値になった文字を直さないため。React 版は食い違いをクライアントで描き直します)。本番のサーバーは `NODE_ENV=production` で起動してください(または SSR のビルドに `define: { 'process.env.NODE_ENV': JSON.stringify('production') }`)。無いとサーバーが開発用の部品も描き、ハイドレーションがグリッドを引き継げません。
- **状態を URL に残す。** 保存した状態は最初の描画で `initialState` に渡し、`onStateChange` で保存し、後からの変化(戻る / 進む)は `grid.applyState(...)` で入れます([状態の保存と復元](/docs/guides/state))。グリッドの通知の中で signal を読んでかまいません(イベントのハンドラと同じく追跡の外で呼びます)。
- **展開行。** `detailRow.render` は行を開いたときに 1 回呼び、行が変わっても呼び直しません(`ctx.row` が今の行)。編集や元に戻すに追従するには JSX の中で `ctx.row` を読んでください。`createSignal(() => ctx.row.x)` で持った入力欄の値は行が変わるたびに戻るので、保存前の入力はふつうの signal で持ちます(`createSignal(untrack(() => ctx.row.x))`)。custom エディタも同じで、`ctx.value` / `ctx.row` は読んだときに引くので JSX の中で読むか、始めの値は `untrack(() => ctx.value)`(または `ctx.initialText`)で取ってください(部品の本体で読むと開発時に Solid が `STRICT_READ_UNTRACKED` を出します)。
- **行の外の値。** `getValue` / `valueFormatter` は行と値だけから決めてください。外の signal を読むと、セルはそれに追従しますが合計(`aggFunc`)は追従しません。その signal が変わったら列を作り直してください(`const columns = createMemo(() => makeColumns(totals()))` など)。
- **複数のグリッドで props を共有する。** 変わらないオブジェクトを spread するか、props を書き並べてください。変化のたびに作り直すオブジェクトを spread しても動きますが、開発時に Solid が `HUGE_FAN_OUT` を出します。
- **Shadow DOM(Web Components)。** `style.css` は Shadow root の中に入れ(`<style>` か `adoptedStyleSheets`)、グリッドは Shadow root の直下に描かずに要素で包み(ポップアップはその要素の中に出ます)、open の Shadow root を使い、`disconnectedCallback` で `render()` が返す `dispose` を呼んでください。詳しくは [API リファレンスの「Shadow DOM の中のグリッド」](/docs/api/props#shadow-dom-の中のグリッド)。
- **開発時の Solid の知らせ。** `vite dev` では、Solid が `autoHeightMeasurer` / `activeRowFollow` / `edit` / `serverSideRowModel` / `fillHandle` / `clampSelectionToRowCount` などの effect の名前(名前は例です)で `EFFECT_RELAY_TEAR` / `EFFECT_WRITES_OWN_SOURCE` を出すことがあります。変化の後にグリッドが状態を合わせ直す処理(React 版も同じ描き直しをしている)で、害は無く、本番のビルドでは出ません。

## 版と変更履歴

Solid 版は React 版・コアとは別の版(0.x)で、コアには同じ 1 つの版で依存します。1.0 より前は minor でも壊す変更が入ることがあり、[Solid 版の変更履歴](https://github.com/ishibashi0112/datasheet-grid/blob/main/packages/solid/CHANGELOG.md)に書きます。TypeScript は 5.8 以上(`moduleResolution` は `bundler` / `nodenext`、`jsx: "preserve"`・`jsxImportSource: "@solidjs/web"`)です。Solid 版の上に作ったライブラリが推論した型を export するときは、Solid 版と core(Solid 版が依存する版)を `peerDependencies` に入れてください。

README は npm の [`@ishibashi0112/spreadsheet-grid-solid`](https://www.npmjs.com/package/@ishibashi0112/spreadsheet-grid-solid) にあります(英語と日本語)。パッケージには API リファレンス(`API_REFERENCE.md`。React 版と同じ文書で、先頭に Solid 版での読み替え)と、AI コーディングツール向けの Skill(`skills/spreadsheet-grid-solid/SKILL.md`)も同梱しています(0.1.2 から。[AI コーディングツールで使う](/docs/ai-assistants))。
