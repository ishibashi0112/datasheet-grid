版は [Semantic Versioning](https://semver.org/lang/ja/) に沿って上げます。React 版 `@ishibashi0112/spreadsheet-grid` と core `@ishibashi0112/spreadsheet-grid-core` は、いつも同じ版で出します。各版の変更は [CHANGELOG](https://github.com/ishibashi0112/datasheet-grid/blob/main/CHANGELOG.md) と [GitHub の Releases](https://github.com/ishibashi0112/datasheet-grid/releases) にあります。

## 版の上げ方

1.0.0 から、次のように上げます。

- major(**X**.0.0): [壊す変更](#壊す変更)。消すものは、その前の minor で[非推奨](#非推奨の手順)にしておきます。
- minor(X.**Y**.0): 機能の追加と非推奨。今の書き方はそのまま動きます。
- patch(X.Y.**Z**): 不具合の修正だけです。
- npm の既定の書き方 `^X.Y.Z` は、同じ major の中の新しい版を受け取ります。major を上げるときは、CHANGELOG のその版の「削除」「挙動の変化」「core の破壊的変更」を確かめてください。

1.0 より前(0.65.0 まで)は、壊す変更も minor で出していました。その変更は CHANGELOG の各版の「挙動の変化」と「core の破壊的変更」にあります。

## 公開範囲

semver の対象は次のものです。

- **React 版**: 入口(`@ishibashi0112/spreadsheet-grid` / `/lite` / `/ai` / `/locales/en` / `/testing`)から import できるもの、CSS ファイル(`style.css` / `style.layer.css` / `themes/*.css`)、[API リファレンス](/docs/api/props)に書いた props・列定義・命令的 API・型とその意味。
- **CSS**: トークン(`--ssg-*`)と、API リファレンスの[スタイリング用の状態クラス(公開契約)](/docs/api/props#スタイリング用の状態クラス公開契約)に載せたクラスと属性。
- **core**: 入口 `@ishibashi0112/spreadsheet-grid-core` と `/testing` から import できるもの。React 版は同じ版の core に依存するので、core も直接使うときは React 版と同じ版にそろえてください(違う版だと core が 2 つ入ります)。

次のものは内部の実装で、どの版でも変わることがあります。

- core の部品(`@ishibashi0112/spreadsheet-grid-core/internal/<dir>/<module>`)。React 版が使う部品で、React 版は同じ版の core に固定で依存します。`internal/` の無い旧サブパス(`@ishibashi0112/spreadsheet-grid-core/<dir>/<module>`)は 0.60.0 で非推奨にし、0.61.0 で消しました。
- 表に載っていない `ssg-*` クラス、DOM の入れ子の形、グリッドが付けるインライン style。

## TypeScript

- 対応するのは TypeScript 5.8 以上です。`moduleResolution` は `bundler`(Vite / Next.js などのバンドラ)か `nodenext`(ESM と CommonJS)。古い `node`(`node10`)は `/lite` などの入口のパスを解決できないので対象外です。
- 公開した型は、公開する前にこの組み合わせ(TypeScript の下限・最新、React 18 / 19 の型、npm / pnpm)で型の検査をしています。

### React 版の上にライブラリを作るとき

社内の共通部品のように、このパッケージの上に作ったものを `declaration: true` で配るときは、列定義や機能の組み合わせを推論のまま export できます(0.65.0 から。型を注釈してもかまいません)。

```tsx
import { createSpreadsheetGrid, findFeature, standardFeatures } from '@ishibashi0112/spreadsheet-grid/lite';

// 注釈しなくても d.ts を出せる(d.ts には公開の入口の名前だけが書かれる)
export const companyFeatures = { ...standardFeatures, find: findFeature };
export const CompanyGrid = createSpreadsheetGrid({ features: companyFeatures });
```

- 出した d.ts には、React 版と core の入口(`@ishibashi0112/spreadsheet-grid` / `@ishibashi0112/spreadsheet-grid-core` など)の名前だけが書かれ、core の内部のパスは書かれません。0.64.0 までで作った d.ts には内部のパスが書かれていることがあるので、0.65.0 以降で作り直してください。これは React 版の入口から使うときの話です。core を直接使う(`createGridEngine` など)ライブラリの d.ts には、core の内部のパスが出ることがあります。
- React 版と core は、同じ版で `peerDependencies` に入れてください(アプリと同じものを使うように)。機能の部品の型 `GridFeature<K>` は、React 版が 2 つ入ると同じ部品でも互いに渡せません。列定義のように core の型が推論に出るものは、pnpm では core が直接の依存に無いと型の名前を書けずにエラー(TS2742 / TS2883。番号は TypeScript の版で違います)になることがあります。

## 壊す変更

次の変更は major で出します。

- 公開 API を消す・改名する、型を狭める
- 既定値や、ドキュメントに書いた挙動を変える
- 公開したトークン・クラス・属性を消す・改名する、付く要素や条件を変える
- 対応ブラウザ・React・TypeScript の下限を上げる

次の変更は壊す変更に入れません(minor か patch)。

- 省略できる prop・関数・型を足す
- ドキュメントに書いたとおりに動くよう不具合を直す
- トークン・クラスを足す、トークンの既定値(色・寸法)を調整する

## 非推奨の手順

消すものは、消す前の minor で非推奨にして、次の major で消します。

1. 型に `@deprecated` の JSDoc を付ける(prop やメソッドはエディタで取り消し線が出ます。選べる文字列の値には出ないので、値は 3 の警告で知らせます)
2. [API リファレンス](/docs/api/props)の行に「**非推奨**」と、消す版を書く
3. 開発ビルドでだけ、使われたときに 1 回、console に警告を出す(本番のビルドでは出しません)
4. CHANGELOG の「非推奨」の節に、代わりに使うものと一緒に書く

警告は日本語の行と英語の行の 2 行です(例は 0.65.0 で出していたもの)。

```text
[spreadsheet-grid] 非推奨: エクスポートの scope `'all'` は 1.0.0 で消します。`'view'` を使ってください(挙動は同じです)。
[spreadsheet-grid] Deprecated: The export scope `'all'` will be removed in 1.0.0. Use `'view'` instead (same behavior).
```

今の非推奨はありません。0.9.0 から非推奨だったエクスポートの scope `'all'`(代わりは `'view'`)と `'visible'`(代わりは `'rendered'`)は、1.0.0 で消しました。
