グリッドはフックを使うクライアントコンポーネントです。サーバーの描画(SSR / SSG)でもエラーや警告なく描けますが、表の中身はハイドレーションの後に出ます。このページでは Next.js(App Router)で使うときの決まりと、気をつけることをまとめます。

## `'use client'` の境界

グリッドを描くコンポーネントは `'use client'` のファイルに置きます。

```tsx
// app/orders/orders-grid.tsx
'use client';

import { useState } from 'react';
import { SpreadsheetGrid, type GridColumn } from '@ishibashi0112/spreadsheet-grid';
import '@ishibashi0112/spreadsheet-grid/style.css';
import type { Order } from './types';

const columns: GridColumn<Order>[] = [
  { key: 'name', title: '品名', width: 200 },
  { key: 'amount', title: '金額', width: 140, valueFormatter: ({ value }) => `${Number(value).toLocaleString()} 円` },
];

export function OrdersGrid({ initialRows }: { initialRows: Order[] }) {
  const [rows, setRows] = useState(initialRows);
  return <SpreadsheetGrid rows={rows} onRowsChange={setRows} columns={columns} rowKeyGetter={(row) => row.id} />;
}
```

```tsx
// app/orders/page.tsx(サーバーコンポーネント)
import { OrdersGrid } from './orders-grid';

export default async function Page() {
  const orders = await getOrders(); // DB や API から
  return <OrdersGrid initialRows={orders} />;
}
```

サーバーコンポーネントからクライアントコンポーネントへは、関数を props で渡せません。次のものは関数を含むので、`'use client'` のファイルの中で作るか import します(サーバーで作って渡すと、開いたときに 500 になり、静的なページはビルドが止まります。型の検査は通るので、書いた時点では気づけません)。

| 関数を含むもの | 置き場所 |
| --- | --- |
| 列定義(`valueFormatter` / `renderCell` / `validate` / `getValue` などを書いた列) | `'use client'` のファイル |
| 英語の文言 `localeTextEn` / `gridAskLocaleTextEn` | `'use client'` のファイルで import し、サーバーからは言語(`'ja'` / `'en'`)だけを渡す([英語と文言](/docs/guides/localization#nextjsapp-router)) |
| `/lite` の `createSpreadsheetGrid` で作ったグリッドと `standardFeatures` | `createSpreadsheetGrid` を呼ぶファイルに `'use client'`([機能を選んで組み込む](/docs/guides/lite)) |
| serverSide の `dataSource`、AI バーの `ask` | `'use client'` のファイル(中から自分の Route Handler を `fetch` する) |

行のデータ(関数を含まない値)はサーバーで作って渡せます。date エディタが読み書きする値は `'YYYY-MM-DD'` の文字列なので、日付の列の値はサーバーで文字列にしておくと、編集した後も同じ形のままです。

CSS(`style.css`)は `app/layout.tsx` で読み込んでも、グリッドを描く `'use client'` のファイルで読み込んでもかまいません。Tailwind CSS と一緒に使うときの読み込み方は [インストール の「Tailwind CSS / HeroUI / Mantine / StyleX との共存」](/docs/installation#tailwind-css--heroui--mantine--stylex-との共存) を参照してください。

## サーバーの描画で出るもの

サーバーで描く HTML は表の骨組みです。

- 行番号と、固定した列(`pinned`)のセルだけを描きます。固定していない列(横の仮想化の対象)は、ハイドレーションの後に描きます。固定列の無い表は、ハイドレーションまで行番号だけの表です。
- JavaScript が動かない環境では、表の中身は出ません。検索エンジンに表の中身を読ませたいページでは、グリッドとは別に HTML の表やテキストを置きます。
- `initialState`(並べ替え・絞り込み・列幅の最初の値)はサーバーの描画から効きます([状態の保存と復元](/docs/guides/state))。

### ダークモード

- `theme="auto"`(OS の配色に従う)は、サーバーでは light で描き、ハイドレーションの後にクライアントの配色へ合わせます。ダークの OS では一瞬明るい表が出ます。
- `<html class="dark">` でダークを切り替えるページ(next-themes など)では `theme="class"` にします。グリッドの配色が CSS だけで決まるので、サーバーの描画からダークになります。
- `motion="auto"` も同じで、サーバーではアニメーションありで描き、ハイドレーションの後に「視差効果を減らす」の設定を見て決め直します。

### `cacheComponents`(Next.js 16)

- グリッドだけなら `<Suspense>` で包まずに、静的なページとして描けます。
- 日付の列の条件(`dateSet` の `condition`)を `initialState` で入れて描くときは、条件を解くために今日の日付を読むので `<Suspense>` で包みます。
- `searchParams` を読む部分は `<Suspense>` の中に置きます(Next.js の決まり)。`layout.tsx` ではなくページの中で包みます(`layout.tsx` で包むと、build は通っても開発時に「searchParams accessed outside of `<Suspense>`」の console.error が出ます)。

## URL から最初の状態を決める

`?sort=qty.desc` のような URL から並べ替えや絞り込みを決めるときは、サーバーコンポーネントで `searchParams` を読んで `initialState` に渡します。サーバーの描画から並べ替えが効きます。例は [状態の保存と復元 の「URL から戻す」](/docs/guides/state#url-から戻す) にあります。

`localStorage` に保存した状態は、サーバーでは読めません。描画中に読むとサーバーとクライアントの HTML が食い違うので、保存した状態から開く画面は、クライアントだけで描くか(`next/dynamic` の `ssr: false` など)、保存先をサーバー(ユーザーの設定など)にして props で渡します。

## 前のページへ戻ったときのスクロール位置

Next.js 16(`cacheComponents`)の画面遷移で前のページへ戻ったとき、グリッドの状態(フィルター・選択・編集の途中)は残りますが、縦のスクロール位置は先頭に戻ることがあります(`<Link>` で移ったときなど、Next.js が隠したページの要素を入れ直すと、ブラウザがスクロール位置を捨てるため。素の `<Activity>` で隠して出すだけなら残ります)。

位置も戻したいときは、`onScroll` で位置を覚えておき、ページが見えたときに `useLayoutEffect` でハンドルの `setScrollPosition` で戻します(`useEffect` では、戻す前に先頭へ戻った位置の `onScroll` が届き、覚えた位置を 0 で上書きすることがあります)。

```tsx
const gridRef = useRef<SpreadsheetGridHandle<Row>>(null);
const scroll = useRef({ top: 0, left: 0 });
// ページが見えたとき(レイアウトの effect はページが表示されるたびに走る)に、描く前に戻す
useLayoutEffect(() => {
  gridRef.current?.setScrollPosition(scroll.current);
}, []);

<SpreadsheetGrid
  ref={gridRef}
  onScroll={({ top, left }) => { scroll.current = { top, left }; }}
  ...
/>
```

## サーバーの API

- **serverSide(SSRM)**: `dataSource.getRows` から自分の Route Handler(`app/api/orders/route.ts` など)を `fetch` します。このサイトの [サーバーサイド行モデル](/docs/guides/ssrm) のデモは、Next.js の Route Handler を実際に叩いています。
- **ことばで絞り込み(`/ai`)**: AI の API キーをブラウザに置かないため、`ask` から自分の Route Handler を呼び、そこで AI を呼びます。Claude / OpenAI / Gemini / Vercel AI SDK の Route Handler の例は [ことばで絞り込み](/docs/guides/ai-filter) にあります。
