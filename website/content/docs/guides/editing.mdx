列は既定で編集できます(`editable` を省略 = 編集可。止めるときは列の `editable: false` か `readOnly: true`、グリッド全体は `readOnly`、セル単位は `canEditCell`)。`column.editor` でエディタ種別を指定します(未指定 = `text`)。値の検証は `column.validate` で行い、`validationMode` で NG 時の動作(`'mark'` = 入るが表示で警告 / `'reject'` = 書き込み拒否)を選べます。

`getValue` だけで `setValue` の無い列(計算列)も既定では編集でき、確定した値は行の `row[key]` に足されるだけで表示(`getValue`)は変わりません。計算列は `editable: false` にするか、`setValue` で元の項目へ書き戻してください(開発時は、行に無いプロパティを足した列ごとに 1 回 console.warn で知らせます)。

## デモ

<EditingDemo />

- **品名** — 必須チェック + `reject`:空で確定しようとするとエディタが拒否します(エラーバブル表示)。Delete での空クリアもスキップされます。
- **数量** — `number` エディタの `min: 0` + `integer: true`(`mark`):負数や小数も入りますが、セルに警告マークが付きます(マウスを乗せたときや、キーボード / タップでそのセルを選んだときに「0 以上で入力してください」などのメッセージ)。`validate` は書いていません。
- **区分** — `select` エディタ:↑↓ で選択、Enter で確定。印字キーで前方一致のタイプアヘッドも動きます。
- **納期** — `date` エディタ:ネイティブの日付ピッカーです。
- **有効** — `checkbox` エディタ:クリック / Space で即トグル(編集セッションなし)。
- **メモ** — 複数行の `text` エディタ(`multiline: true`)+ `autoHeight`:`Alt+Enter`(または `Ctrl` / `⌘+Enter`)で改行、`Enter` で確定。値の改行どおりに表示して行が伸びます。

## エディタ種別

```tsx
const columns: GridColumn<Row>[] = [
  { key: 'name', title: '品名', width: 190, editable: true },                       // text(既定)
  { key: 'qty', title: '数量', width: 120, editable: true,
    editor: { type: 'number', min: 0, integer: true } },   // 0 以上の整数(検査にもなる)
  { key: 'category', title: '区分', width: 140, editable: true,
    editor: { type: 'select', options: [
      { label: '通常', value: '通常' },
      { label: '特注', value: '特注' },
    ] } },
  { key: 'dueDate', title: '納期', width: 150, editable: true,
    editor: { type: 'date' } },
  { key: 'active', title: '有効', width: 110, editable: true,
    editor: { type: 'checkbox' } },
]
```

`number` / `date` / `checkbox` には既定の「文字列 → 値」パーサが付き、**貼り付け / Delete クリア / エディタ確定で共通**に効きます(例: number 列を Delete でクリアすると `null` になる)。number 列は全角の数字・符号・小数点と 3 桁区切りも数値として読みます(`１，２３４` や Excel の `1,234` を貼り付けると `1234`)。セルを選んで `-5` や `.5` のようにマイナス / 小数点から打ち始めても、そのまま数値(`-5` / `0.5`)になります。明示の `parseClipboardValue` は常に優先されます。

独自 UI で編集したい場合は `{ type: 'custom', render: (ctx) => <MyEditor ... /> }` を使います。返した要素は編集中のセルと同じ大きさの透明な枠の中に描くので、根の要素に `width: 100%` / `height: 100%` と背景色を付けてください([列の API の注意点](/docs/api/column))。`ctx.commit(value)` / `ctx.cancel()` で確定・キャンセルします。編集が終わった後(確定 / 取消 / 別のセルの編集が始まった後)に呼んだ前の編集の `ctx.commit` / `ctx.cancel` は何もしません(`ctx.commit` は `{ status: 'noop' }` を返します)。エディタを開いたままグリッドの中の別のセルや見出しを押すと、確定しなかった編集は終わります(値は書きません)。押したときに打った値を残したいときは、組み込みのエディタと同じく入力欄の `onBlur` で `ctx.commit(value)` を呼んでください。

## 改行を含む値(`multiline`)

既定の text エディタは 1 行の入力欄で、ブラウザが改行を消します(改行を含む値を開いて直すと、確定したときに改行が無くなる)。改行を含む値の列は `editor: { type: 'text', multiline: true }` にすると、複数行の入力欄で編集できます。入力欄は中身に合わせて下へ伸び、表の見える範囲の下端で止まってその中でスクロールします。

```tsx
{ key: 'note', title: 'メモ', width: 240, autoHeight: true,
  editor: { type: 'text', multiline: true } }                       // Enter で確定、Alt+Enter で改行(Excel と同じ)
{ key: 'body', title: '本文', width: 320, autoHeight: true,
  editor: { type: 'text', multiline: true, enterKey: 'newline' } }  // Enter で改行、Ctrl / ⌘+Enter で確定
```

| `enterKey` | `Enter` | 改行 | 確定 |
| --- | --- | --- | --- |
| `'commit'`(既定。Excel と同じ) | 確定して下へ | `Alt+Enter` / `Ctrl+Enter` / `⌘+Enter` | `Enter` / `Tab` |
| `'newline'`(メモ帳やチャットに近い) | 改行 | `Enter` / `Shift+Enter` / `Alt+Enter` | `Ctrl+Enter` / `⌘+Enter` / `Tab` |

どちらも `Tab` は確定して右へ、`Escape` は取り消し、フォーカスアウトは確定です。改行を表示するのは `autoHeight` の列(値の改行どおりに折り返して行が伸びる)で、それ以外の列は 1 行に並べて表示します。

## Enter 確定後の移動先(`editorEnterMove`)

組み込みエディタの `Enter` 確定後、アクティブセルは既定で **1 行下**へ移動します(Excel 同様)。`editorEnterMove` prop で変更できます:

```tsx
<SpreadsheetGrid editorEnterMove="none" ... />  // 'down'(既定) | 'up' | 'right' | 'left' | 'none'
```

`'none'` は移動せずその場に留まります。ラベル行(`labelRow`)には止まらず、同じ向きの次のデータ行へ進みます(先がラベル行だけなら確定した行に留まります)。`Tab` / `Shift+Tab`(右 / 左)には影響しません。custom エディタは `ctx.commit(value, direction)` の第 2 引数で方向を渡してください(本 prop の対象外)。

移動先は「確定を反映した再レンダー後」の行数でクランプされるため、`onRowsChange` で末尾に空行を追加する入力グリッド(貼り付け + 直接入力の定石パターン)では、最終行の `Enter` 確定でそのまま増えた行へ進めます。

## コードから編集を始める / フォーカスを戻す

「行を追加」ボタンで足した行をすぐ編集させるときは、命令的 API の `startEditing(viewRowIndex, colIndex)` を使います(`F2` と同じ。セルを選んで見える位置へスクロールし、エディタにフォーカスが移ります)。位置は表示の位置なので、並べ替えや絞り込みの中では `rows.findIndex` ではなく行キーから `getViewRowIndex(rowKey)` で、列は `getColIndex(columnKey)` で引きます。

```tsx
import { flushSync } from 'react-dom';

const addRow = () => {
  const row = { id: crypto.randomUUID(), name: '' };
  flushSync(() => setRows((prev) => [...prev, row])); // グリッドが新しい行を知ってから引く
  const grid = gridRef.current;
  const viewRowIndex = grid?.getViewRowIndex(row.id) ?? -1;
  const colIndex = grid?.getColIndex('name') ?? -1;
  if (viewRowIndex >= 0 && colIndex >= 0) grid?.startEditing(viewRowIndex, colIndex);
};
```

右クリックメニューから開いたモーダルを閉じた後など、キーがグリッドへ届かなくなったときは `focus()` でグリッドへフォーカスを戻せます(`imeDirectInput` 有効時は入力受けへ)。詳しくは [命令的 API](/docs/api/handle#フォーカス--編集の開始) を参照してください。

## 外からの変更も「元に戻す」で戻せるようにする

グリッドの外のボタン(「選んだ行を削除」など)で `rows` を差し替えると、元に戻すの履歴は消えます(グリッドの外の変更はグリッドが知らないため)。元に戻せるようにしたい変更は、`setRows` の代わりに命令的 API の `applyRows(nextRows)` で渡します。履歴に積んでから `onRowsChange` へ渡すので、`Ctrl/Cmd+Z` で戻せます。

```tsx
const deleteSelected = () => {
  const keys = new Set(gridRef.current?.getSelectedRowKeys() ?? []);
  gridRef.current?.applyRows(rows.filter((row) => !keys.has(row.id)));
};
```

## バリデーション

```tsx
{
  key: 'name', title: '品名', width: 190, editable: true,
  validate: ({ value }) => String(value ?? '').trim() !== '' || '品名は必須です',
  validationMode: 'reject', // 既定は 'mark'
}
```

- **`'mark'`(既定)** — 値は書き込み、セルに警告表示(背景 + 右上マーカー + メッセージ。メッセージはマウスを乗せたときと、キーボード / タップでそのセルを選んだときに出ます)。判定は表示時に導出されるため、貼り付け・undo・外部からの `rows` 差し替え後も常に実データと整合します。
- **`'reject'`** — 書き込み自体を拒否。エディタ確定は「拒否 + 編集継続 + エラーバブル」、貼り付け / クリア / [フィルハンドル](/docs/guides/fill-handle)は NG セルだけスキップされます。

### 数値の範囲と整数(組み込みの検査)

number エディタの `min` / `max` と `integer: true`(整数だけ)は、そのまま値の検査になります。`validate` を書かなくても、範囲外や小数のセルに印が付きます(`validationMode: 'reject'` なら書き込みません)。

```tsx
{ key: 'qty', title: '数量', width: 120, editable: true,
  editor: { type: 'number', min: 0, integer: true } }       // 0 以上の整数
{ key: 'rate', title: '割合', width: 120, editable: true,
  editor: { type: 'number', min: 0, max: 1, step: 0.01 } }  // 0〜1(小数可)
```

- 検査の順番は「数値か → 整数か → 範囲内か」で、最初に引っかかったものがメッセージになります(「数値で入力してください」「整数で入力してください」「0 以上で入力してください」など)。
- 空のセルは通します。必須にしたいときは `validate` で書きます。
- `validate` と併用すると `validate` が先です。`validate` の NG はそのメッセージのまま出て、`validate` が通した値だけを組み込みの検査にかけます。
- `step` は ↑↓ キーとスピナーの刻みだけで、検査には使いません。

保存前の一括チェックは命令的ハンドルの `getInvalidCells()` を使います。マークを「送信時にだけ」表示する `showValidationMarks` prop と組み合わせた業務フォームのレシピは [API リファレンス](/docs/api/column#バリデーションvalidate--validationmode) を参照してください。
