列は既定で編集できます(`editable` を省略 = 編集可。止めるときは列の `editable: false` か `readOnly: true`、グリッド全体は `readOnly`、セル単位は `canEditCell`)。`column.editor` でエディタ種別を指定します(未指定 = `text`)。値の検証は `column.validate` で行い、`validationMode` で NG 時の動作(`'mark'` = 入るが表示で警告 / `'reject'` = 書き込み拒否)を選べます。

`getValue` だけで `setValue` の無い列(計算列)も既定では編集でき、確定した値は行の `row[key]` に足されるだけで表示(`getValue`)は変わりません。計算列は `editable: false` にするか、`setValue` で元の項目へ書き戻してください(開発時は、行に無いプロパティを足した列ごとに 1 回 console.warn で知らせます)。

## デモ

<EditingDemo />

- **品名** — 必須チェック + `reject`:空で確定しようとするとエディタが拒否します(エラーバブル表示)。Delete での空クリアもスキップされます。
- **数量** — `number` エディタの `min: 0` + `integer: true`(`mark`):負数や小数も入りますが、セルに警告マークが付きます(マウスを乗せたときや、キーボード / タップでそのセルを選んだときに「0 以上で入力してください」などのメッセージ)。`validate` は書いていません。
- **区分** — `select` エディタ:↑↓ で選択、Enter で確定。印字キーで前方一致のタイプアヘッドも動きます(IME で確定した日本語の名前は、その文字で始まる候補へ、無ければその文字を含む候補へ)。
- **納期** — `date` エディタ:`Enter` / `F2` / ダブルクリックではブラウザの日付の入力欄が開きます。セルを選んで `2026/3/15` のように打ち始めると文字の入力欄で開き、確定するときに日付として読みます(読めなければ「日付で入力してください」と出して編集を続けます)。
- **有効** — `checkbox` エディタ:チェックボックスそのものを押すか、Space で即トグル(編集セッションなし。セルのチェックボックスの外を押したときはアクティブセルになるだけ)。
- **メモ** — 複数行の `text` エディタ(`multiline: true`)+ `autoHeight`:`Alt+Enter`(または `Ctrl` / `⌘+Enter`)で改行、`Enter` で確定。値の改行どおりに表示して行が伸びます。

## エディタ種別

```tsx
const columns: GridColumn<Row>[] = [
  { key: 'name', title: '品名', width: 190, editable: true },                       // text(既定)
  { key: 'qty', title: '数量', width: 120, editable: true,
    editor: { type: 'number', min: 0, integer: true } },   // 0 以上の整数(検査にもなる)
  { key: 'category', title: '区分', width: 140, editable: true,
    editor: { type: 'select', options: [
      { label: '通常', value: '通常' },
      { label: '特注', value: '特注' },
    ] } },
  { key: 'dueDate', title: '納期', width: 150, editable: true,
    editor: { type: 'date' } },
  { key: 'active', title: '有効', width: 110, editable: true,
    editor: { type: 'checkbox' } },
]
```

`number` / `date` / `checkbox` には既定の「文字列 → 値」パーサが付き、**貼り付け / Delete クリア / エディタ確定で共通**に効きます(例: number 列を Delete でクリアすると `null` になる)。number 列は全角の数字・符号・小数点と 3 桁区切りも数値として読みます(`１，２３４` や Excel の `1,234` を貼り付けると `1234`)。セルを選んで `-5` や `.5` のようにマイナス / 小数点から打ち始めても、そのまま数値(`-5` / `0.5`)になります。明示の `parseClipboardValue` は常に優先されます。

Excel の通貨や会計の書式のセル(`¥12,000` / `12,000円` / `(1,200)`)を貼り付ける列は、組み込みの数値のパーサ `numberParser` を `parseClipboardValue` に渡します。読み方は number 列の既定と同じ(全角・3 桁区切りも読む)で、`strip` の文字を先に外し、`negativeParentheses` でかっこの数を負の数として読みます(1.1.0 から)。貼り付けで書かなかったセル(編集できないセルと、`validationMode: 'reject'` の列で検査に通らなかった値)は `onPasteSkipped` で 1 回の貼り付けにつき 1 回まとめて受け取れるので、「3 セルは書きませんでした」のように知らせられます。

```tsx
import { numberParser } from '@ishibashi0112/spreadsheet-grid';

{ key: 'amount', title: '金額', width: 120, editable: true,
  editor: { type: 'number', min: 0 }, validationMode: 'reject',
  parseClipboardValue: numberParser({ strip: ['¥', '￥', '円'], negativeParentheses: true }) }

<SpreadsheetGrid
  onPasteSkipped={({ cells }) => toast(`${cells.length} セルは書きませんでした(${cells[0]?.message ?? '編集できないセル'})`)}
/>
```

値と表示名が別の select 列(値 `'transport'` / 表示名「交通費」)は、select エディタに `clipboard: 'label'` を書くと、コピーと CSV が表示名になり、Excel から貼り付けた表示名は値へ読み替えます(値はそのまま、どちらでもない文字は生のまま。1.1.0 から)。セルの表示名は `valueFormatter` で出します([値と表示名が別の列](/docs/guides/value-labels))。

```tsx
const KINDS = [{ value: 'transport', label: '交通費' }, { value: 'meal', label: '会議費' }];
{ key: 'kind', title: '区分', width: 120, editable: true,
  editor: { type: 'select', options: KINDS, clipboard: 'label' },
  valueFormatter: ({ value }) => KINDS.find((o) => o.value === value)?.label ?? String(value ?? '') }
```

独自 UI で編集したい場合は `{ type: 'custom', render: (ctx) => <MyEditor ... /> }` を使います。返した要素は編集中のセルと同じ大きさの透明な枠の中に描くので、根の要素に `width: 100%` / `height: 100%` と背景色を付けてください([列の API の注意点](/docs/api/column))。`ctx.commit(value)` / `ctx.cancel()` で確定・キャンセルします。編集が終わった後(確定 / 取消 / 別のセルの編集が始まった後)に呼んだ前の編集の `ctx.commit` / `ctx.cancel` は何もしません(`ctx.commit` は `{ status: 'noop' }` を返します)。組み込みのエディタはフォーカスが外れたときに確定します。custom エディタも入力欄の `onBlur` で `ctx.commit(value)`(または `ctx.cancel()`)を呼んでください。呼ばないと、エディタを開いたままグリッドの中の別のセルや見出しを押したときにエディタが開いたまま残り、別のセルをダブルクリックするまでグリッドのキー操作が効きません。`onBlur` でサーバーの検査を待ってから `ctx.commit` を呼ぶ作りでも、値は編集していたセルに書かれます。同じ編集が続いている間は `render(ctx)` の部品を作り直しません(1.3.0 から。上に行が足されたときも)。 英字のキーで打ち始めたときはそのキーが `ctx.initialText` に入るので、入力欄の初期値にしてください。グリッドの `imeDirectInput` を使うときは、エディタの定義に `imeDirectInput: true` を付けると IME で確定した文字も `ctx.initialText` に入ります(1.2.0 から。[キーボード / タッチ操作](/docs/guides/keyboard#ime-オンのまま打ち始めるimedirectinput))。

## 改行を含む値(`multiline`)

既定の text エディタは 1 行の入力欄で、ブラウザが改行を消します(改行を含む値を開いて直すと、確定したときに改行が無くなる)。改行を含む値の列は `editor: { type: 'text', multiline: true }` にすると、複数行の入力欄で編集できます。入力欄は中身に合わせて下へ伸び、表の見える範囲の下端で止まってその中でスクロールします。

```tsx
{ key: 'note', title: 'メモ', width: 240, autoHeight: true,
  editor: { type: 'text', multiline: true } }                       // Enter で確定、Alt+Enter で改行(Excel と同じ)
{ key: 'body', title: '本文', width: 320, autoHeight: true,
  editor: { type: 'text', multiline: true, enterKey: 'newline' } }  // Enter で改行、Ctrl / ⌘+Enter で確定
```

| `enterKey` | `Enter` | 改行 | 確定 |
| --- | --- | --- | --- |
| `'commit'`(既定。Excel と同じ) | 確定して下へ | `Alt+Enter` / `Ctrl+Enter` / `⌘+Enter` | `Enter` / `Tab` |
| `'newline'`(メモ帳やチャットに近い) | 改行 | `Enter` / `Shift+Enter` / `Alt+Enter` | `Ctrl+Enter` / `⌘+Enter` / `Tab` |

どちらも `Tab` は確定して右へ、`Escape` は取り消し、フォーカスアウトは確定です。スマートフォンなどのソフトキーボードでは `Alt` / `Ctrl` を押せないため、既定の `'commit'` では改行できません。モバイルで改行させたい列は `enterKey: 'newline'` にしてください(確定は外をタップ = フォーカスアウト)。改行を表示するのは `autoHeight` の列(値の改行どおりに折り返して行が伸びる)で、それ以外の列は 1 行に並べて表示します。

## 編集中にグリッドを外すとき

組み込みのエディタはフォーカスが外れたときに確定します。編集中にグリッドごとアンマウントすると(キーボードのショートカットで画面のタブを切り替えたときなど)フォーカスアウトが起きないため、打っていた値は捨てられます(`display: none` で隠したときや、マウスでタブを押したときはフォーカスアウトで確定します)。外す前に確定させたいときは、外す処理の先頭で入力欄の `blur()` を呼んでください。グリッドが `onRowsChange` を呼んでから外れます。

```tsx
const switchTab = (next: string) => {
  // 編集中の値を確定してから外す
  if (document.activeElement instanceof HTMLElement) document.activeElement.blur();
  setTab(next);
};
```

## Enter 確定後の移動先(`editorEnterMove`)

組み込みエディタの `Enter` 確定後、アクティブセルは既定で **1 行下**へ移動します(Excel 同様)。`editorEnterMove` prop で変更できます:

```tsx
<SpreadsheetGrid editorEnterMove="none" ... />  // 'down'(既定) | 'up' | 'right' | 'left' | 'none'
```

`'none'` は移動せずその場に留まります。ラベル行(`labelRow`)には止まらず、同じ向きの次のデータ行へ進みます(先がラベル行だけなら確定した行に留まります)。`Tab` / `Shift+Tab`(右 / 左)には影響しません。custom エディタは `ctx.commit(value, direction)` の第 2 引数で方向を渡してください(本 prop の対象外)。

移動先は「確定を反映した再レンダー後」の行数でクランプされるため、`onRowsChange` で末尾に空行を追加する入力グリッド(貼り付け + 直接入力の定石パターン)では、最終行の `Enter` 確定でそのまま増えた行へ進めます。

## コードから編集を始める / フォーカスを戻す

「行を追加」ボタンで足した行をすぐ編集させるときは、命令的 API の `startEditing(viewRowIndex, colIndex)` を使います(`F2` と同じ。セルを選んで見える位置へスクロールし、エディタにフォーカスが移ります)。位置は表示の位置なので、並べ替えや絞り込みの中では `rows.findIndex` ではなく行キーから `getViewRowIndex(rowKey)` で、列は `getColIndex(columnKey)` で引きます。

```tsx
import { flushSync } from 'react-dom';

const addRow = () => {
  const row = { id: crypto.randomUUID(), name: '' };
  flushSync(() => setRows((prev) => [...prev, row])); // グリッドが新しい行を知ってから引く
  const grid = gridRef.current;
  const viewRowIndex = grid?.getViewRowIndex(row.id) ?? -1;
  const colIndex = grid?.getColIndex('name') ?? -1;
  if (viewRowIndex >= 0 && colIndex >= 0) grid?.startEditing(viewRowIndex, colIndex);
};
```

右クリックメニューから開いたモーダルを閉じた後など、キーがグリッドへ届かなくなったときは `focus()` でグリッドへフォーカスを戻せます(`imeDirectInput` 有効時は入力受けへ)。詳しくは [命令的 API](/docs/api/handle#フォーカス--編集の開始) を参照してください。

## 外からの変更も「元に戻す」で戻せるようにする

グリッドの外のボタン(「選んだ行を削除」など)で `rows` を差し替えると、元に戻すの履歴は消えます(グリッドの外の変更はグリッドが知らないため)。元に戻せるようにしたい変更は、`setRows` の代わりに命令的 API の `applyRows(nextRows)` で渡します。履歴に積んでから `onRowsChange` へ渡すので、`Ctrl/Cmd+Z` で戻せます。

```tsx
const deleteSelected = () => {
  const keys = new Set(gridRef.current?.getSelectedRowKeys() ?? []);
  gridRef.current?.applyRows(rows.filter((row) => !keys.has(row.id)));
};
```

### 編集中に行が動いた・消えたとき

編集していた行が並べ替えや上への行の追加で動いたときは、エディタも付いていきます(打ちかけはそのままで、custom エディタも作り直しません)。行が絞り込みから外れたとき(`rows` にはまだある。「今日」の絞り込みで日付が変わったときなど)は、打ちかけを確定してその行へ書き、フォーカスはグリッドに残ります(1.3.0 から)。

- text / number / date のエディタは打ちかけを書きます。custom エディタは入力欄の `onBlur` で `ctx.commit` を呼んでいればその値を書き、select は取り消します。
- 書けない行(`canEditCell` が `false`。渡す位置は外れる前の位置)と、検査で reject する値は書きません。
- `rows` が別の行に替わって編集していた行が無くなったとき(行キーで探します)と serverSide では取り消します。

1.2.x までは知らせずに編集を終え(打ちかけは捨てる)、フォーカスがページの `body` に落ちてキー操作が効きませんでした。

### 外から絶えず変わる表(ライブの更新)

株価や在庫のように外から `rows` が絶えず変わる表は、更新を `applyRows(next, { undoable: false })` で渡します(1.1.0 から)。履歴に積まず、今の履歴も消さないので、利用者が直したメモを `Ctrl/Cmd+Z` で戻すと、その後の株価の更新は残ったままメモだけが元に戻ります(やり直すも同じ)。`rows` を作り直して `setRows` で渡すと履歴が消え、`undoable` を付けずに `applyRows` で渡すと更新の 1 つずつが履歴に積まれて `Ctrl/Cmd+Z` が株価を巻き戻します。

`applyRows` は関数の形(`(prev) => next`)も受け取ります。`prev` は最後に渡した行なので、フィードのコールバックで最新の `rows` を ref に持たなくて済みます。行は `rowKeyGetter` で対応づけるので、行が増えたり消えたりする表では `rowKeyGetter` を書いてください(書かずに行の数が変わったときと、行キーが重なっているときは、1.0 と同じく編集の前の行をそのまま戻すので、外からの更新も戻ります)。

```tsx
useEffect(() => {
  const unsubscribe = feed.subscribe((prices) => {
    gridRef.current?.applyRows(
      (prev) => prev.map((row) => (prices[row.symbol] === undefined ? row : { ...row, price: prices[row.symbol] })),
      { undoable: false },
    );
  });
  return unsubscribe;
}, []);

<SpreadsheetGrid ref={gridRef} rows={rows} onRowsChange={setRows} rowKeyGetter={(row) => row.symbol} columns={columns} />
```

並べ替えたまま値が変わる表(前日比の大きい順の株価ボードなど)では、既定ではアクティブセルが表示位置(何行目か)に残るので、銘柄が入れ替わるたびに別の銘柄を指します(Excel と同じ)。押した銘柄に付いていかせるには `activeCellFollows="row"` を書きます(1.2.0 から)。

<LiveSortDemo />

```tsx
<SpreadsheetGrid activeCellFollows="row" rowKeyGetter={(row) => row.symbol} /* ... */ />
```

- 同じ行の何列かの範囲は一緒に動き、何行かにまたがる範囲は、範囲の中の銘柄が入れ替わったら外してアクティブセルの 1 セルにします(選んだつもりの無い銘柄がコピーや集計に入るため。アクティブセルの銘柄が動かなくても同じです)。全部の行にまたがる範囲(`Ctrl+A` など)と列の選択はそのままです。
- 表はスクロールしません。画面の外へ動いたら、矢印キーを押すとそのセルまで動きます。
- 追う行が消えた・絞り込みで隠れたときは位置に残ります。選択のドラッグ中は動かさず、離したときに付いていきます。
- 行の追加 / 削除でも付いていくには `rowKeyGetter` を書いてください(無いと行のキーは `rows` の中の位置なので、上の行を消すと同じキーが別の行を指します)。
- `onActiveCellChange` は位置だけ動いたときは呼ばれません(セルを動かしたときだけ)。
- `rows` を渡す表(clientSide)だけです。serverSide は並べ替えがサーバーで、取り直すまで並びが変わらないので位置に残ります。編集中のセルは既定でも行に付いていきます。
- 並べ替えの列を編集して確定し、その行が動いたときは、`Enter` は確定する前の並びで下にあった行へ、`Tab` は編集した行の隣のセルへ動きます(続けて入力する行が飛ばない)。既定の `'position'` は確定した後の並びのその位置の下 / 隣です。

## バリデーション

```tsx
{
  key: 'name', title: '品名', width: 190, editable: true,
  validate: ({ value }) => String(value ?? '').trim() !== '' || '品名は必須です',
  validationMode: 'reject', // 既定は 'mark'
}
```

- **`'mark'`(既定)** — 値は書き込み、セルに印(背景 + 右上の三角 + メッセージ)を出します。
- **`'reject'`** — 書き込み自体を止めます。エディタの確定は「止めて編集を続け、エラーの吹き出し」、貼り付け / クリア / [フィルハンドル](/docs/guides/fill-handle)は通らないセルだけ飛ばします。
- number エディタの `min` / `max` / `integer: true` は、`validate` を書かなくてもそのまま値の検査になります。

印を出す時を決める `showValidationMarks`、保存前にまとめて確かめる `getInvalidCells()`、メッセージの言語などは [入力の検査](/docs/guides/validation) にまとめています。
