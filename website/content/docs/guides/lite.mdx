---
title: バンドルを小さくする(/lite)
description: createSpreadsheetGrid で使う機能だけを組み込み、初期読み込みの JS を約半分にする
---

`SpreadsheetGrid` は全機能入りで、初期読み込みの JS は約 120KB(gzip)です。`@ishibashi0112/spreadsheet-grid/lite` の `createSpreadsheetGrid` を使うと、渡した機能だけを入れたグリッドを作れます。渡さなかった機能のコードはバンドルに入りません。

`/lite` は 0.54.0 で追加しました。

```tsx
import { createSpreadsheetGrid, standardFeatures } from '@ishibashi0112/spreadsheet-grid/lite';
import '@ishibashi0112/spreadsheet-grid/style.css';

// モジュールの先頭で 1 回だけ作る(コンポーネントの中では作らない)
const Grid = createSpreadsheetGrid({ features: standardFeatures });

export function OrdersTable() {
  return <Grid rows={rows} columns={columns} rowKeyGetter={(row) => row.id} />;
}
```

`Grid` は `SpreadsheetGrid` と同じ props・`ref` ハンドル・型で使えます。全部入りから移るときは、使っている機能を `features` に入れて、`SpreadsheetGrid` を `createSpreadsheetGrid` で作ったコンポーネントに置き換えます。

## 試してみる

機能を選ぶと、その組み合わせで作ったグリッドに切り替わります。どの機能の違いも見えるよう全機能の prop を渡しているので、入れていない機能の分は何も起きません。各機能の右の説明が試し方です。

## どれだけ小さくなるか

| 構成 | 初期 JS(gzip) |
| --- | --- |
| 全部入り(`SpreadsheetGrid`) | 約 120KB |
| `/lite` 機能なし | 約 65KB |
| `/lite` + `standardFeatures` | 約 84KB |
| `/lite` + `standardFeatures` + `serverSideFeature` | 約 88KB |

esbuild で minify し、React を外部化して計測した値です(`@tanstack/virtual-core` を含む)。バンドラーによって数 KB 前後します(0.61.0 の全部入りの実測で、Vite 8(Rolldown)は esbuild より約 1.5KB 小さく、Vite 7(Rollup)はほぼ同じ。Next.js 16 では webpack が Turbopack より約 4KB 大きくなりました)。機能ごとの増え方は [API リファレンス](/docs/api/lite)の表にあります。

## 機能の選び方

機能なしでも、表示(仮想スクロール・固定列)、選択、キー操作、編集、コピー / 貼り付け、元に戻す、列幅の変更、ソート、行選択、展開行、`getState` / `applyState` が動きます。そこへ要る機能を `{ キー: 部品 }` で足します。部品の名前は「キー + `Feature`」です。

```tsx
import {
  createSpreadsheetGrid,
  standardFeatures,
  findFeature,
  serverSideFeature,
} from '@ishibashi0112/spreadsheet-grid/lite';

// プリセットに検索と SSRM を足す
const Grid = createSpreadsheetGrid({
  features: { ...standardFeatures, find: findFeature, serverSide: serverSideFeature },
});
```

機能の組み合わせを変数にして export するとき(社内の共通部品のパッケージなどで `declaration: true` のとき)は、型 `GridFeatures` を注釈してください。注釈しないと推論された型が公開していない内部の型を指し、型の宣言(d.ts)を出すときに TS2742 になります。

```tsx
import type { GridFeatures } from '@ishibashi0112/spreadsheet-grid/lite';

export const companyFeatures: GridFeatures = { ...standardFeatures, find: findFeature };
```

- `standardFeatures` は、列フィルター / グローバルフィルター(`filtering`)、列メニュー(`columnMenu`)、ツールパネル(`toolPanel`)、列幅の自動調整(`columnAutosize`)、エクスポート(`export`)です。
- 列見出しからソートする入口は列メニューです。列メニューが無いときに画面からソートできるのは、ツールパネル(`toolPanel`)の「並び替え」タブだけです(どちらも無いと `applyState` 等の API からになります)。
- 列フィルターを画面から掛ける入口は列メニューの「フィルター…」です。`filtering` だけでは検索欄しか使えないので、列フィルターも使うなら `columnMenu` も入れてください。
- ツールパネル(`toolPanel`)は列メニューの項目や適用中フィルターのチップから開きます。`columnMenu` か `filtering` と一緒に入れてください(どちらも無いと開く入口が無いので何もしません)。
- 列メニューの「幅の自動調整」は `columnAutosize` を入れたときだけ出ます。
- 全部入りで既定オンの機能(列フィルター・列メニュー・列のドラッグ・選択範囲の集計・コピー範囲の点線など)は、`/lite` では入れたときだけ既定オンになります。

## 全部入りから移るとき

全部入りでは prop を書かずに使える機能があり、`/lite` では入れないと消えます。prop を渡していないので開発時の警告も出ません。全部入りと同じ既定の動きにするには、次の表の機能をすべて入れます。

| 全部入りで prop を書かずに使える機能 | キー | `standardFeatures` |
| --- | --- | --- |
| 列フィルター / グローバルフィルター | `filtering` | 入っている |
| 列メニュー | `columnMenu` | 入っている |
| ツールパネル(列メニューの項目から開く) | `toolPanel` | 入っている |
| 列の境界のダブルクリックでの幅の自動調整 | `columnAutosize` | 入っている |
| 列見出しのドラッグでの並べ替え(`onColumnsChange` を渡したとき) | `columnReorder` | 入っていない |
| 選択範囲の集計(下部バー) | `selectionAggregates` | 入っていない |
| コピー範囲の点線(`Ctrl/Cmd+C` のあと) | `motionExtras` | 入っていない |

```tsx
import {
  createSpreadsheetGrid,
  standardFeatures,
  columnReorderFeature,
  selectionAggregatesFeature,
  motionExtrasFeature,
  type GridFeatures,
} from '@ishibashi0112/spreadsheet-grid/lite';

// 全部入りと同じ既定の動き(ここから使わない機能を外す)
const features: GridFeatures = {
  ...standardFeatures,
  columnReorder: columnReorderFeature,
  selectionAggregates: selectionAggregatesFeature,
  motionExtras: motionExtrasFeature,
};
const Grid = createSpreadsheetGrid({ features });
```

ほかの機能(検索・フィルハンドル・行ドラッグ・SSRM など)は prop を渡したときだけ動くので、渡している prop があれば開発時の警告が足す機能を名指しします。

## 入れていない機能を使おうとしたとき

入れていない機能の prop を渡したり、その機能のメソッドを呼んだりしても、何も起きません(エラーにもなりません)。開発ビルドでは、prop ごとに 1 回だけ、足すべき機能を名指しした警告が出ます(prop を持たないエクスポートとツールパネルは、`exportCsv()` / `openFilterManager()` などのメソッドを呼んだ時点で警告します。`openFilterManager()` はフィルタータブを開くので、`filtering` が無いときも警告します):

```text
[spreadsheet-grid] prop `fillHandle` が渡されましたが、その機能が機能セットに入っていないため何もしません。createSpreadsheetGrid の features に `fillHandle: fillHandleFeature` を入れてください。
```

本番ビルドでは警告を出しません(警告の処理ごとバンドルから消えます)。

列定義を `filtering` の入ったグリッドと入っていないグリッドで共有するときは、入っていない方に `enableColumnFilter={false}` を書くと、列の `filterType` の警告は出ません(その列定義のフィルターを使わないことが分かるため)。

いくつかの機能は、無いときに別の動きになります。

- `filtering` が無いと、検索欄と列フィルターは出ません。`applyState` で渡したフィルターは状態には入りますが、行は絞り込まれません(上部 / 下部バーの「Filter: …」にも数えません)。
- `serverSide` が無いと、`dataSource` を無視して `rows` で動きます。
- `labelRow` が無いと、ラベル行もデータ行として並びます。
- `grouping` が無いと、`rowGroup` の列はグループ化せずにそのまま表示します。

## 注意

- `createSpreadsheetGrid` はモジュールの先頭で呼んでください。コンポーネントの中で呼ぶと描画のたびに別のコンポーネントになり、グリッドの状態(選択・スクロール位置・編集中の値など)が消えます。そうなっているときは開発時に `console.warn` で知らせます(`useMemo` で 1 回だけ作る形は警告しませんが、eslint-plugin-react-hooks の `static-components` が指摘するのでモジュールの先頭を勧めます)。
- Next.js(App Router)では、`createSpreadsheetGrid` を呼ぶファイルに `'use client'` を付けてください。作ったコンポーネントや `standardFeatures` は関数なので、サーバーコンポーネントから props で渡せません(クライアントコンポーネントの中で import して使います)。
- 機能の組み合わせは作ったときに決まります。途中で機能を足したいときは、別の組み合わせで作ったコンポーネントに切り替えてください。
- 全部入りの `SpreadsheetGrid` と同じアプリで混ぜることはできますが、`/lite` は機能ごとのファイルに分けた別のビルドなので共通部分を共有しません。同じページで両方を使うと共通部分が二重に入り、ページを分けても `/lite` だけのページが大きくなることがあります(Next.js 16 の Turbopack の実測で、`standardFeatures` のページが約 85KB → 約 92KB)。どちらかの入口に揃えてください。
- 使わない機能がバンドルから落ちることは、Vite 8・webpack 5・Next.js 16(既定の Turbopack)・esbuild で確かめています(バンドラーが `package.json` の `sideEffects` と `/* @__PURE__ */` を解釈する必要があります)。
- テストで列フィルターやツールパネルを開くときの `preloadGridPopups()` は、`/lite` から import してください(入口ごとに部品が別なので、全部入りの入口のものでは `/lite` のグリッドの部品は読み込まれません。[テスト](/docs/guides/testing#ポップオーバーを開くテスト))。
