モーダル(shadcn/ui・Radix・Headless UI・HeroUI・Mantine の Modal / Dialog、素の `<dialog>`)やポップオーバーの中にグリッドを置けます。列メニュー・列フィルター・右クリックメニュー・select エディタの候補・ツールパネル・フィルハンドルのメニュー・ツールチップ・ドラッグのゴーストは、**グリッドを囲むダイアログの中**に出ます(1.1.0 から)。

## デモ(顧客を選ぶダイアログ)

<DialogDemo />

- 「ダイアログで開く」で素の `<dialog>` を `showModal()` で開きます。列見出しの ⋮ の列メニュー、「地域」のダブルクリックの候補、右クリックメニューはダイアログの中に出て、そのまま押せます。
- `popupContainer="body"` にすると、ポップアップは `document.body` の直下に出て、ダイアログ(トップレイヤー)の後ろに隠れて見えません(1.0.2 までの動き)。

## ポップアップの場所(`popupContainer`)

| 値 | 描く場所 |
| --- | --- |
| `'auto'`(既定) | グリッドを囲むいちばん近いダイアログ(`<dialog>` / `popover` 属性の要素 / `aria-modal="true"` / `role="dialog"` / `role="alertdialog"`)の中。無ければ、Shadow root の中のグリッドはその Shadow root の直下でグリッドを包む要素の中(1.3.0 から。[Shadow DOM の中のグリッド](/docs/api/props#shadow-dom-の中のグリッド))、それ以外は `document.body` の直下。ダイアログが中を切る fixed の基準のとき(Mantine の Modal の中身)は、外側の `position: fixed` の祖先の中(下の「気をつけること」) |
| `'body'` | いつも `document.body` の直下(1.0 までと同じ) |
| 要素 | その要素の中 |
| 関数 | グリッドの要素を受け取って描く場所を返す(`null` / `undefined` なら `document.body`)。ポップアップを開いている間の描画ごとに呼ぶ。閉じている間は呼ばない |

`document.body` の直下では、モーダルの中で使えないことがあります。素の `<dialog>` の `showModal()` と `popover` はトップレイヤーに出るので、body の直下の要素はその後ろに隠れます。Radix(shadcn/ui)・React Aria(HeroUI)・Headless UI のモーダルは、外側のポインタを止め(body に `pointer-events: none`)、フォーカスを中に閉じ込め、外側の押下で閉じるので、body の直下のポップアップは押せず、入力もできません。Radix の Dialog と Popover は `aria-modal` を付けないので、`role="dialog"` で見つけます。

```tsx
// shadcn/ui の Dialog: 何も書かなくても、ポップアップは DialogContent の中に出る
<Dialog>
  <DialogContent>
    <SpreadsheetGrid rows={rows} columns={columns} />
  </DialogContent>
</Dialog>

// 描く場所を自分で決める
<SpreadsheetGrid rows={rows} columns={columns} popupContainer={(grid) => grid.closest<HTMLElement>('.sheet-frame')} />
```

場所はポップアップを開くたびに決めます。グリッドを入れた `<dialog>` を後から `showModal()` で開いても、その中に出ます。ポップアップはダイアログの最後の子として足し、閉じると外します。

## 気をつけること

- **ずれの打ち消し**: 描く場所の祖先に `transform` / `translate` などがあると(shadcn/ui の DialogContent は `translate` で真ん中に置く)、`position: fixed` の基準がその要素になります。グリッドはそのずれを測り、ポップアップの `translate` で打ち消します(開いたときと、位置を決め直すたび)。拡大縮小(`scale`)は打ち消しません。
- **ダイアログの枠で切れる**: その要素が `overflow` で中を切り、しかも `transform` などで `position: fixed` の基準になると(`max-height` と `overflow-y: auto` と `transform` を持つダイアログ)、ポップアップもダイアログの枠で切れます。`'auto'` は、外側に `position: fixed` の祖先があればそこへ出します(Mantine の Modal は中身の外側の `.mantine-Modal-inner` へ出るので切れません)。外側に無いとき(中身自身が `position: fixed` で `overflow-y: auto` の DialogContent など)は切れるので、切らない場所を要素か関数で渡してください(ダイアログがその外のポインタやフォーカスを止めないなら `'body'` でもかまいません)。
- **トークン**: 表で決めた CSS トークン(`--ssg-*`)は、これまでどおり開いたときにポップアップへ写します。`theme="class"` の `dark` のクラスは `<html>` か `<body>` に付けてください。
- **自分で出すポップアップ**: custom エディタや `renderCell` の中で利用側が出すポップアップ(候補の一覧など)は `popupContainer` の対象外です。`document.body` へポータルすると、モーダルの `<dialog>` の中では後ろに隠れて押せません。グリッドと同じく、囲むダイアログの中へ出してください(`createPortal(list, anchor.closest('dialog') ?? document.body)`。`anchor` はエディタの入力欄など。Radix などのモーダルなら、そのライブラリの Portal の `container` に同じ要素を渡します)。
- **Escape**: グリッドが使う `Escape`(編集の取り消し・メニューを閉じるなど)ではダイアログは閉じません。詳しくは [キーボード操作の「ダイアログの中のグリッド」](/docs/guides/keyboard#ダイアログの中のグリッド)。
