## 背景: 素の jsdom ではグリッドが描画されない

jsdom はレイアウトを計算しないため、素の jsdom では実グリッドの行・列が 1 本も描画されません。

- **縦方向**: グリッドはスクロール要素の `clientHeight` / `clientWidth` を読んで可視行数を決めますが、jsdom では 0 のため行が出ません。
- **横方向**: 列仮想化(`@tanstack/virtual-core`)はスクロール要素の矩形を **ResizeObserver の通知**から得るため、`observe()` が no-op のスタブだと幅 0 のまま列が描画されません(`getBoundingClientRect` のスタブだけでは不足)。

## installJsdomLayoutStubs

`@ishibashi0112/spreadsheet-grid/testing` サブパスの `installJsdomLayoutStubs()` が上記をまとめて解決します(React 非依存の小さなモジュール)。

```ts
// @vitest-environment jsdom
import { beforeAll } from 'vitest';
import { installJsdomLayoutStubs } from '@ishibashi0112/spreadsheet-grid/testing';

beforeAll(() => {
  installJsdomLayoutStubs(); // 既定 1200×600
});
```

寸法を変えたい場合はオプションで指定します。teardown が必要なスイートでは返り値の restore 関数を使います。

```ts
const restore = installJsdomLayoutStubs({ width: 800, height: 400 });
afterAll(restore);
```

スタブを 2 回入れたとき(スイートの `beforeAll` と個々のテストなど)は、入れたのと**逆の順**に戻してください。同じ順に戻すと、先に入れたスタブの値が残ります。

インストールされるスタブ:

| 対象 | 内容 |
| --- | --- |
| `HTMLElement.prototype.clientHeight` / `clientWidth` | 固定値を返す getter |
| `Element.prototype.getBoundingClientRect` | 固定矩形(`width` × `height`) |
| `globalThis.ResizeObserver` | `observe()` 時に**即時コールバック**するスタブ |
| `Element.prototype.scrollTo` | 未定義のときのみ no-op を補う |

## 描かれる範囲

スタブは「見えている大きさ」を決めるだけで、仮想化はそのまま効きます。既定の 1200×600 なら、描かれるのは高さ 600px に入る行と幅 1200px に入る列(それぞれ先読みの分を足した数)です。既定の行の高さ(36px)と幅 120px の列なら、約 38 行・約 18 列です。グリッドの `height` を変えても、描かれる量はスタブの大きさで決まります。

```tsx
const { container } = render(<SpreadsheetGrid rows={rows} columns={columns} />);

// 行・セルの描画(行は固定ペインにも描かれ、行番号は左のペインの行にあるので、中央のペインの行で数える)
expect(container.querySelectorAll('[data-pane="center"].ssg-body-row')).toHaveLength(rows.length); // 行が少ないとき

// getRowClassName / cellClassName で付与したクラス
expect(container.querySelectorAll('.ssg-body-cell.my-warn-cell')).toHaveLength(2);
```

全行・全列を描きたいとき、または先の行を確かめたいときは、次のどちらかにします。

- **スタブを大きくする**: `installJsdomLayoutStubs({ width: 3000, height: 4000 })` のように、表の全体が入る大きさにします(100 行 × 120px の列 20 本ならこれで全部描かれます)。
- **スクロールする**: 表本体(`.ssg-scroll-container`)の `scrollTop` / `scrollLeft` を書いてから `fireEvent.scroll` を出します。

```tsx
const scroller = container.querySelector<HTMLElement>('.ssg-scroll-container')!;
scroller.scrollTop = 80 * 36; // 行の高さ 36px で 80 行目あたりへ
fireEvent.scroll(scroller);
```

ハンドルの `scrollToRow` / `scrollToCell` は jsdom では何もしません(スタブの `scrollTo` は何もしないため)。

セルを引くときは、中央のペインの行の中で `aria-colindex` を使えます(行番号の列が 1、最初のデータ列が 2)。読み上げの名前や役割(`role="gridcell"` / `role="columnheader"` など)は [アクセシビリティの表](/docs/api/props#アクセシビリティ)にあります。

状態クラスの一覧(公開契約)は [SpreadsheetGrid props の「スタイリング用の状態クラス」](/docs/api/props#スタイリング用の状態クラス公開契約)を参照してください。

## よく書く操作

| 操作 | 書き方 |
| --- | --- |
| 貼り付け | グリッドは paste イベントの `clipboardData` を読みます。user-event なら、セルを押してから `await user.paste('a\tb\nc\td')`(`user.keyboard('{Control>}v{/Control}')` では貼り付きません)。fireEvent なら `fireEvent.paste(shell, { clipboardData: { getData: () => 'a\tb' } })`(`shell` は `.ssg-shell`)。 |
| コピー | グリッドは `navigator.clipboard.writeText` で書きます。user-event の `userEvent.setup()` はクリップボードを差し替えるので、`Ctrl+C` の後に `await navigator.clipboard.readText()` で中身を確かめられます。user-event を使わないときは `navigator.clipboard` を `{ writeText: vi.fn() }` などに差し替えます。 |
| 範囲選択 | jsdom には座標が無いので、ポインタのドラッグでは正しい範囲になりません。`Shift+矢印` / `Shift+クリック`、またはハンドルの `selectRange` を使います。 |
| 確定・取り消しの後 | 確定(`Enter` / `Tab`)の後のアクティブセルの移動と、次の編集を受け付けるようになるのは、その後のマイクロタスクです。fireEvent で同期に続けて書くときは、間に `await act(async () => {})` を挟みます(結果を確かめるだけなら `waitFor` でも構いません)。 |
| エディタの入力欄を取る | 編集中は、エディタの枠(`role="group"`)と入力欄の両方が「(列名) を編集」の名前を持ちます。`getByLabelText('品名 を編集')` は 2 つに当たって落ちるので、`getByRole('textbox', { name: '品名 を編集' })`(number は `spinbutton`、select は `combobox`)で取ります。 |
| date エディタ | ネイティブの `<input type="date">` なので、`fireEvent.change(input, { target: { value: '2026-11-09' } })` で値を入れます(jsdom の一般的な制約)。 |
| ハンドルでセルを選んだ後のキー操作 | `selectCell` / `setActiveCell` はフォーカスを移しません。続けてキーを送るときは、ハンドルの `focus()` を呼ぶか、セルを押します。 |
| ポップオーバーを開いた後のフォーカス | 列フィルターのポップオーバーの入力欄へフォーカスが移るのは、開いてから 2 フレーム後(位置が決まってから)です。`await waitFor(() => expect(input).toHaveFocus())` で待ちます。`Escape` などで閉じたときは、すぐにグリッドへ戻ります(1.0.2。パネルの中のボタンからはその場で、入力欄からはパネルが外れた直後 = `fireEvent` の後の `await act(async () => {})` か user-event の後。blur で確定する入力欄を `Escape` で確定しないため)。 |
| 実ブラウザ(Playwright など)で列見出しの ⋮ を押す | マウスのある環境では、見出しの操作(⋮ と並べ替えのつまみ)は見出しへポインタを乗せたときだけ現れ、それまではポインタを受けません。`locator.click()` の前に見出しへ `hover()` します(幅 120px 以上の見出しでは、⋮ は乗せたときに文字の後ろへ並ぶ)。 |

## Jest で使うとき

React 版は CommonJS の入口も持つので、Jest でもそのまま読み込めます。CSS の import は Jest が読めないため、`moduleNameMapper` で読み替えます。

```js
// jest.config.js
module.exports = {
  testEnvironment: 'jsdom',
  moduleNameMapper: { '\\.css$': 'identity-obj-proxy' },
};
```

Jest 30 の jsdom(26)には `PointerEvent` がありません。グリッドはセルの選択をポインタのイベントで受けるため、`fireEvent.pointerDown` / `fireEvent.click` だけではセルが選ばれません。セルを押す操作は user-event(`await user.click(cell)`)で書くか、ハンドルの `selectCell` と `focus()` を使います。

## ポップオーバーを開くテスト

列フィルターのポップオーバーとツールパネル(フィルター管理 / 列の表示 / 並び替え)の部品は、別のチャンクから遅延読み込みされます([インストール](/docs/installation#遅延読み込みされる部品))。読み込みが終わる前は表示されないため、開いた直後に**同期で**中身を確かめるテストでは、先に `preloadGridPopups()` で読み込んでおきます。

```ts
import { beforeAll } from 'vitest';
import { preloadGridPopups } from '@ishibashi0112/spreadsheet-grid';

beforeAll(async () => {
  await preloadGridPopups();
});
```

`/lite` の `createSpreadsheetGrid` で作ったグリッドでは、`preloadGridPopups` も `@ishibashi0112/spreadsheet-grid/lite` から import してください(入口ごとに部品が別です)。

`findBy*` / `waitFor` で表示を待つテストなら、`preloadGridPopups()` は無くても動きます。

## 偽のタイマーを使うとき

`dateSet` の相対プリセット(今日 / 今月 / 過去 30 日 / カスタム)を列フィルターに掛けている間、グリッドは日付の変わり目を見張るタイマー(最大 1 時間ごとに張り直す)を持ちます。`vi.useFakeTimers()` の下で `vi.runAllTimers()` を呼ぶとこのタイマーが尽きないため、上限回数で打ち切られます。時刻を進めたいときは `vi.advanceTimersByTime()` / `vi.runOnlyPendingTimers()` を使ってください(相対プリセットが掛かっていなければタイマーはありません)。
